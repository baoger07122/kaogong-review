# Web → 原生 iOS 同步清单

## 1. 用途

本文件用于记录 Web 预览版每次修改中，需要在原生 iOS App 重新实现或验证的内容。

工作日优先在 Web 预览版快速修改和验证；周末冻结本周需求后，原生重写工作树按照本文件逐项实现、验收并生成 IPA。

原生版同步的是功能行为、数据规则和验收结果，不是直接复制 Web 页面代码。

## 3. 状态定义

- `待评估`：Web 已修改，尚未判断原生版如何实现。
- `待同步`：确认原生版需要实现。
- `实现中`：原生分支正在开发。
- `待验收`：原生实现完成，等待对照测试。
- `已同步`：已进入指定 IPA 并通过验收。
- `仅 Web`：只用于预览环境，原生版不需要实现。
- `暂缓`：需求尚未稳定，本周不进入原生版。

## 4. 变更分类

- `视觉`：颜色、字号、间距、图标、卡片和布局。
- `交互`：点击、滑动、拖拽、动画、键盘、震动和页面跳转。
- `修复`：已有功能错误修复。
- `功能`：新增或扩展功能。
- `数据`：字段、数据库、备份、恢复和迁移。
- `API`：云端接口、登录、同步和服务器行为。
- `原生能力`：通知、文件、Pencil、快捷键、窗口和系统集成。

## 8. 强制规则

1. Web 页面、功能或交互发生用户可见变化后，必须更新本文件。
2. 数据字段、备份格式或 API 有变化时，优先级必须标记为 `高`，并写明旧 IPA 的兼容策略。
3. 原生实现不得只以“看起来相似”为完成标准，必须按照验收步骤验证。
4. Web 和原生使用不同技术实现，但同一业务字段的含义必须一致。
5. 涂鸦、速算、富文本和思维导图重写前，必须先记录现有行为和历史数据格式。
6. `已同步` 必须填写原生提交和 IPA 版本，不能只凭代码完成判断。
7. 每次周末发布后保留历史记录，不删除已完成条目。

## 9. 紧急同步条件

以下情况不得等待周末：

- 数据丢失、覆盖或无法读取
- App 无法启动或持续崩溃
- 内容无法保存
- 云同步损坏或账号异常
- 备份无法生成或恢复
- 正式 API 与已安装 IPA 不兼容
