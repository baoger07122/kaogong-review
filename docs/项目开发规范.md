# 考公复盘系统项目开发规范

## 1. 适用范围

本规范适用于 `kaogong-review` 后续所有功能开发、问题修复和界面调整。

## 2. 统一实现原则

新增功能必须先检查系统中是否已经存在相同或相近的功能。

如果存在，应优先复用已有的：

- 数据服务
- 弹窗组件
- 选择器组件
- 确认框组件
- 卡片结构
- 按钮样式
- 编辑器交互

不应在相同功能已经存在的情况下，重新制作一套外观或交互不同的实现。

## 3. 弹窗规范

新增、编辑、选择和确认类弹窗统一使用居中弹窗风格：

- 半透明页面遮罩
- 白色圆角卡片
- 标题和关闭按钮
- 灰色取消按钮
- 蓝色主操作按钮
- 弹窗打开时锁定背景滚动
- 点击遮罩关闭时正确恢复页面滚动

除非有明确的交互需求，不新增底部滑出式弹窗。

## 4. 数据兼容规范

已有用户数据不得因为界面重构被删除或无提示覆盖。

涉及字段调整时：

- 优先复用已有字段，避免同一含义出现两套字段
- 为历史空值提供可理解的显示兜底
- 删除配置时，不直接删除关联正文数据
- 老数据格式需要保留读取和展示兼容
- 结构性迁移需要提供明确的回退或备份策略

## 5. 编辑器规范

不同编辑场景应按实际需求提供最小功能集合。

便签等轻量内容不得直接引入完整笔记编辑器的全部工具。格式栏只显示已经实现并且当前场景需要的功能。

编辑器工具栏必须：

- 保持编辑选区
- 不遮挡正在输入的内容
- 不与 Safari 原生工具栏重复叠加
- 在软键盘和 iPad 分屏环境下保持可用

## 6. 修改流程

每次修改前：

1. 检查最新 `main` 代码
2. 检查 `git status`
3. 检查当前版本号
4. 说明计划修改的文件
5. 优先进行局部修改

每次修改后：

1. 运行语法检查
2. 构建 `index.html`
3. 检查构建产物版本号
4. 检查 `git diff --check`
5. 提交并推送 `main`
6. 部署后验证线上版本和关键流程

## 7. 受保护功能

涂鸦功能和速算练习功能属于受保护模块。除非用户明确要求，不得重写其功能逻辑、数据结构或主要样式。

## 8. 变更说明

面向不熟悉代码的用户，用普通语言说明：

- 改了什么
- 为什么这样改
- 对已有数据有什么影响
- 可能存在什么风险
- 如何验证是否生效
