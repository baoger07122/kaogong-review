# 图形推理新增「默卡」模式

## 入口和现状

行测 → 判断推理 → 图形推理 → 错题列表。当前 `LibraryView` 使用 `graphDisplayMode` 记住「卡片」「闪卡」两种模式。「卡片」显示题图、题干和错题属性，「闪卡」使用独立正反面。图推考点及图形规律会给出解题提示。用户要第三种模式，卡片面仅保留原题内容供默练。

## 目标

- 模式从左到右为「卡片」「默卡」「闪卡」。在现有切换栏的前两项之间插入「默卡」，三项共用 `graphModeButton`。沿用现有控件位置、38 × 28 pt 按钮、12 pt semibold、已选强调色、外层圆角、组内间距及窄窗口适配。可访问性播报名称及已选态。
- 默卡沿用错题列表现有瀑布流、卡片尺寸、白底、圆角、边距、题图缩略图和题干字体。卡片面仅显示原题题图、题干。单独录入的选项随详情查看，原题图内已有的选项随原图显示。图题缺少题干时只显示题图，缺图时保留题干。图文均缺失用现有无题干占位。禁止以笔记、规律、摘要代替题干。
- 卡片面省略考点、错因标签、类型、图形规律、思路、错因说明、提醒、笔记、掌握状态、标记、日期、来源、题号属性、答案和颜色反馈；不留空行或同类内容的隐藏辅助语义。原题题干与原题图中的内容照原样保留。内容较长沿用题图缩略图和题干预览规则，点开可看完整题目。图数提示属于附加文字，默卡面省略。
- 默卡独立于标签管理里设置的卡片顶部。普通「卡片」仍使用其配置；「闪卡」仍走现有正反面的行为。默卡点按沿用题目详情入口和既有详情内容规则，长按沿用列表操作。浏览或切换默卡不会提交作答、更改复习进度或修改错题。

## 实现和数据

- 在 `LibraryView` 现有 `@AppStorage("native.library.graphDisplayMode")` 增加稳定值 `memoryCards`。旧的 `cards`、`flashcards` 暂存值照常读取，未知值回退卡片。只在 `isGraphReasoningContext` 为真时应用默卡。现有筛选、排序、分页限额与记录身份保持。
- 从列表将一个明确的题干预览模式传给 `LibraryMasonryGrid`、`LibraryErrorRecordCard` 以及估高。默卡走题图加题干的渲染分支，保留原浏览入口；避免构建隐藏的标签、错因和标记视图。切换模式更新瀑布流分栏缓存，切回普通模式还原对应信息。复用已有题干快照与题图的缓存和按需解码，核对快照的旧字段回退，避免将属性摘要当成原题显示。
- 使用现有模式持久化机制，设置模块隔离，不改记录或写入额外复习数据。用户同时报告图推打开详情持续加载，按本轮另一个热修规格独立验证详情路径。

## 验收

1. 图推中准备一条有题图、题干、考点、错因标签和规律的题，确认现有切换栏从左到右是「卡片」「默卡」「闪卡」。依次点按，核对三个按钮的尺寸、间距和选中样式沿用现有组件。默卡面只看到题图和题干，卡片顶部配置两类标签时依旧不泄露。
2. 默卡中点开、退出、再点开同一道和另一道图推题，确认详情加载和回退正常。仅切模式和浏览时，答案、复习次数、掌握状态保持原值。
3. 检查仅图、仅文字、旧图题、多图、单独选项以及窄分屏。核对普通卡片与闪卡仍支持原有交互，其他模块无默卡入口。退出重进图推后模式保留。
4. 按本轮发布约定检查和归档，与当前待发布批次合并，禁止为同一提交重复触发构建。用户不要求等待结果返回。
