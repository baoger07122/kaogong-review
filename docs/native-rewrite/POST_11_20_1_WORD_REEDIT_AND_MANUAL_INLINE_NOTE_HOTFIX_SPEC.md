# 词语重开编辑与错题笔记手动保存热修复

2026-11-20。用户已授权 Luna 实现本批热修复。以 11.20.1（build 154，下载清单提交 `6c4dd7e`）为对照，执行时核对发布分支。范围为词语库重开编辑、行测错题详情笔记的输入显示及保存。本批沿用现有卡片页面，前一份跨页面卡顿方案单独留档。

## 1. 新建词语保存后重开无法编辑

### 现有行为与定位

进入「编辑词语库」，用户截图显示正文可读、橙色锁提示「暂时无法安全编辑这段内容，原内容已保留」，保存灰置。它对应 `LibraryRecordEditorView.swift:1152` 的保护预览分支。编辑区和保存按钮均依赖 `PreparedLibraryWordContent.editableAttributedText`。

`prepareWordContent` 先走原生富文本渲染，再无条件将降级解析器的 `parseForEditing` 和 `supportsLosslessEditing` 用作是否开放编辑的门槛（约 1320–1347 行）。保留编辑的降级解析器会拒绝常见但它无法还原的 CSS、链接和附件。普通词语保存 HTML 使用原生 `NSAttributedString` 导出，原生渲染成功的内容也可能因降级门槛被拦。截图可以确定触发保护的分支。该条记录具体被哪种 HTML 属性拦截需要原始载荷才可复现。

### 修复与验收

- 将原生编辑快照的资格与降级路径分别判断。先尝试忠实读取 App 自己保存的 HTML 与受支持富文本。原生快照须核对正文、段落与附件完整，明确识别失败或安全占位。降级的严格无损检查只用于实际采用该结果编辑时。保留未知、截断、异常标记及超安全边界内容的只读保护。以正常渲染结果的可验证完整性开放编辑。
- 沿用原有「编辑词语库」「保存」及编辑区。无修改时保留原 HTML。实际编辑后仅更新所属字段，单词对应正文、辨析组对应辨析正文，关联错题、分类和其他字段沿用原值。解析失败时完整原文保留并可查看，取消时使用原记录。
- 复现用 App 实际导出的 HTML 完成「新建保存 → 返回 → 重开编辑 → 加一段字 → 保存 → 重开」。覆盖单词、辨析组、段落／粗体、原生导出常见的 CSS、可安全还原的图片／内部链接，以及异常附件保护。重点检查正常原生快照可用但受限降级器拒绝的用例。旧保护预览在升级后重新执行编辑资格判断，沿用原数据。

## 2. 错题笔记尾部换行、光标及内容不可达

### 已知范围

用户视频 `fcac8c8e117309baae39dd175c619639.mp4` 约 13.87 秒。分屏中外接键盘和触摸操作后，尾部内容缺少正常的增长及光标反馈。约 8.4–9.0 秒可见触摸选区手柄和编辑菜单，说明至少部分触摸选区事件能到编辑器。视频只呈现在屏结果，未取到文本存储长度、编辑版本及首响应者状态。

用户进一步确认，输入数行后会到一条边界行。光标只能停在该行开头。键盘、手指和笔都无法把光标移到该行后面的有效位置。继续打字和回车没有可见变化，退格仍能删除。这一组合是本轮重点复现条件。`shouldChangeTextIn` 的会话输入锁在退格分支之前，若同一时刻确实能删，持续的全输入锁解释力较弱。需核对插入是否进入文本存储、选区是否回到行首，以及实际末行能否参与布局和命中。

`LibraryInlineNoteView.noteCanvasMinimumHeight` 为 360 pt 最小高度。该入口使用外部滚动容器，`NativeRichTextEditor.swift:1613` 在随内容增高的模式关闭内层滚动。约 1854–1899 行同宽时优先读取 TextKit 的 `usageBoundsForTextContainer`。高度更新即使等于旧值也会清空重测标记。换行、末尾空行或布局尚未扩大时，现有缓存可能过早被标为有效，使实际输入、光标命中及滚动范围停在旧高度。普通改字没有固定行数上限。现有输入锁在完成流程中可拒绝键入，需作为独立状态核对。

### 修复与验收

- 仅对行测内嵌错题笔记的随内容增高路径修正。正文修订、末行与编辑宽度为测量依据。使用新修订布局；若 TextKit 使用区仍陈旧，或末尾插入位置超出测量范围，在下一布局节拍安排一次新测量并更新外层高度。计入末尾空行和插入光标。光标移动时在需要时才调整滚动位置。保留同修订、同宽缓存与现有样式，避免每次选区变更都重排整窗。
- 区分文本没有进入、选区移了但未显示、文本已进入后被旧快照回填，以及尾部高度或命中仍使用旧范围。必要时用开发日志记录编辑请求类型、变更前后的 UTF-16 文本长度、选区偏移、修订号、视图与测量高度、焦点与输入锁。用实际文本长度和文档终点校验选区，避免普通更新重置已移动的光标。日志不包含正文。完成失败、取消或旧请求结束，均按当前会话解锁，过期请求无法改变新题输入。
- 验收用空白及有格式的长笔记，逐行输入超过初始高度。分屏下分别覆盖普通段落和编号段落，在边界行做「方向键移动 → 点行尾 → 输入数字与文字 → 连续回车 → 退格 → 再输入」。验证光标到达已存在的文字后方，新增文字及换行在编辑器中即时可见，删除后能继续插入。确认正式完成后回读末句、换行、原图片和段落完整。行测之外复用编辑器的现有行为按具体入口回归。

## 3. 行测错题笔记只在点击「完成」后提交

### 现有入口

`LibraryInlineNoteView` 目前在 `draft` 改变后延时约 1.4 秒捕获快照并排队提交。切后台、视图消失及恢复未提交草稿也有提交路径。`LibraryRecordDetailView` 的编辑或涂鸦等入口还可以通过会话的 `finish` 间接进入原完成流程。关闭文字变更监听里的定时任务后，仍须收口其它路径。

### 保存契约

- 行测错题详情的笔记采用显式保存策略。从行测入口传入策略，共用视图的其他业务入口依其原策略处理。编辑期间维护 UIKit 中的最新文本和未保存状态，标题处沿用原有 11 pt 状态和 14 pt 蓝色「完成」。状态使用「未保存」「保存中…」「已保存」。停顿打字时只更新编辑会话。正式错题记录、索引和同步相关版本仅由用户点「完成」提交。
- 覆盖退后台、离开、重进恢复、照片／工具异步回调、兼容旧失败草稿及导航触发的 `finish`。离开时保留未提交的可恢复本地草稿，重进展示为未保存，须由「完成」提交。编辑停顿期间以会话内存为主。旧草稿与现有数据发生版本冲突时，上下展示「题目当前保存内容」和「未保存草稿」；操作按钮按顺序为蓝色「以恢复草稿为准」、次级「保留当前内容」，确认冲突处理后才能继续编辑。两按钮水平间距 12 pt；窄窗口改为左对齐垂直排列、行距 8 pt，字号 13 pt、半粗。依赖已保存正文的题目编辑入口提示先点「完成」。程序触发的离场、涂鸦切换及后台恢复只写本地可恢复草稿，不代替用户提交。
- 点「完成」时确认输入法组合态，取当前题和当前会话的最新快照，包括末行及图片。沿用现有版本和附件校验、写入确认与失败恢复。按保存时锁策略防重复提交，失败恢复可编辑状态并保留当前草稿，再点「完成」重试。结束成功后清理相匹配的恢复草稿。

### 验收与发布

1. 编辑后等待超过旧防抖周期，切后台和切题。核对正式笔记与错题记录版本未改变。重进显示原未保存草稿，点「完成」一次，确认正式记录保存。重复点击和源版本冲突分别核对。
2. 验证照片插入完成及附件操作中点击「完成」的处理。保存失败后可继续打字，旧会话回调不会删改另一题。确认词语编辑和其他调用方未受行测手动保存策略影响。
3. 针对三个问题使用可用的非模拟器行为检查及 iOS 目标编译归档。云端模拟器退出本批流程。发布遵守项目一次有效运行的约定。交付注明代码、编译归档、IPA 可下载及实机未覆盖的范围。若用户愿意在完整修复版验收，集中一次。
