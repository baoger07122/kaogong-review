# 错题详情刷新与申论原型本地交付

- 发布目标：11.27.2 / Build 168；基线为 11.27.1 / Build 167。

实现依据见 [本轮规格](../ERROR_DETAIL_LOCAL_REFRESH_SPEC.md)。

- 根据错题涂鸦录屏及源码，确认工具栏收起后错题详情仍可能重新读取同一条记录。现有刷新容器会保留旧画面并禁用整个区域。本轮把交互限制收窄到旧内容区，保留外层滚动。编辑、涂鸦和预览保存都交接与新记录数据完全一致的解码快照，索引复用已准备的对象。
- 按当前打开的「申论录入与图层」原型，将预录参考答案折叠、已有参考答案状态、图层面板内新建及重命名落实到原生页面。现有评分、作答、材料和笔迹存储继续由原有仓库负责。
- 检查了本地差异和 Swift 解析相对基线。用 Chromium 在 1100 px 和 550 px 上核对原型的答案折叠、图层新建和笔迹显隐。新增 Swift 行为用例覆盖大记录缓存命中、等长不同内容及跨记录隔离。
- Windows 工作区没有本地 Swift/Xcode，原生编译、Swift 行为用例执行、真机滚动和涂鸦实测待确认。原型浏览器检查仅证明对照原型的行为。
- 发布约定已更新。本轮源码和指定行为检查纳入 11.27.2 / Build 168 发布批次。
- 首次发布 run `45942823372` 的领域检查、编译、申论模型测试和答案/复盘 UI 测试通过；缩放 UI 测试因新详情布局下的固定视口坐标未打开倍率菜单而失败，归档未执行。测试改为点击已出现的 `shenlun-reader-zoom` 控件，并按 `200%` 无障碍标识选择预设后复验。
- 第二次发布 run `45945763795` 仍因两秒缩放浮层在无障碍查询前消失而失败，归档未执行。为不改变普通用户行为，申论缩放 UI 测试现在传入专用启动参数，使控件在该测试期间保持可见；测试仍执行捏合、打开倍率菜单、选择 `200%`，并继续核对纸面宽度及涂鸦画布对齐。
- 第三次发布 run `45947894806` 的编译、领域检查和选定模型测试通过，但申论 UI 测试在非本轮范围的“普通”显示分段切换后反复等待动画空闲，12 分钟超时，未进入缩放测试。移除该非核心显示切换，保留作答完成、复盘保存和成绩保存断言，避免无关动画阻塞发布验收。
