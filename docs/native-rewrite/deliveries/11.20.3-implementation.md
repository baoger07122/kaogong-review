## Implemented behavior

- Selected-tag search: flow height now follows the content with a 28 pt internal minimum; existing 8 pt vertical padding and 44 pt outer minimum keep the empty single-row field at 44 pt and let wrapped selections grow.
- Tag display: Xingce tag settings separately control knowledge-point and mistake-tag visibility in error attributes and at the card top. Concrete types override module defaults; quantity question types use generated IDs migrated on rename and removed on delete. Hiding editor/detail attributes does not delete stored references. Card tags are resolved in the snapshot and shared by display and masonry height estimation.
- Free-text causes: data analysis, verbal logic-fill, and quantity-relation causes render one trimmed, non-empty newline item per vertical row; long text wraps within its item and punctuation such as commas does not split it. The masonry estimate counts each item and its wrapping. Detail editing retains the selected legacy cause key and string/array shape; quantity legacy `、` separation and `weaknessTags` compatibility remain supported.
- Graph-reasoning detail loading: loading state is keyed to record identity, payload version, and request ID. Stale results are ignored; missing data, decode errors, cancellation, and timeout enter a recoverable state with a retry action. Logs contain only short identifiers, request IDs, and byte counts. The question-bank route and manual note-saving behavior are unchanged.
- Graph-reasoning memory cards: the selector reads `卡片｜默卡｜闪卡`; the new persisted `memoryCards` mode displays only the question image and the `question` field prompt using the existing masonry cards. It omits separately entered options, tags, feedback, and review metadata. The grid reflows when its display mode changes.
- Home todo dates: the row shows unpadded `M.d` and gives each date a common right edge. The calendar/local date rules remain unchanged; completed records use completion date, with planned-date fallback for older records. Existing behavior assertions now cover the short date and a single-digit month/day.
- Home todo typing: new/edit todo and daily-todo editor drafts now live in their form subviews. The Home view retains only the initial draft and receives the full draft on Save. Today’s parsed todo list and progress are derived once per Home render rather than repeatedly. Save failure leaves the form open with its text intact; ordinary typing is not debounced or autosaved.
