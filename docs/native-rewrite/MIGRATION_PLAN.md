# 原生数据迁移与回滚计划

## 第一阶段迁移策略

原生 App 首先导入现有 `考公备考系统-backup.json`。导入器不尝试一次性把所有字段强制映射到固定 Swift 结构，而是：

1. 校验顶层版本和集合类型。
2. 将每条记录按原始 JSON 保存到原生本地数据库。
3. 额外提取集合、ID、创建时间、更新时间、科目和模块用于查询。
4. 未识别字段原样保留。
5. 全部解析成功后一次保存；失败则回滚。

这样可以先保证“不丢数据”，再按模块逐步建立强类型模型。

## 正式切换前

1. Web 版导出最新完整备份。
2. 校验备份包含错题、笔记、套卷、待办、复盘任务、词语、便签、倒数日、标签和 keyvalue。
3. 原生测试版导入并生成数量对照报告。
4. 随机抽查富文本、图片、涂鸦、申论扩展字段和关联 ID。
5. 原生重新导出，再由兼容性测试验证 Web 能读取。
6. 验收通过后才把正式 Bundle ID 从 `.nativebeta` 切换为正式 ID。

## 回滚

- Web `main` 和 Render 始终独立保留。
- 冻结标签 `web-baseline-v8.25.3` 永不移动。
- 原生迁移初期不删除 Web 数据。
- 每次结构迁移前自动生成一份 JSON 备份。
- 原生导入失败必须回滚当前事务并保留导入前数据。

## 已知风险

- Web 富文本历史上存在 HTML、Markdown 和 JSON 块三种格式，需要专门转换与对照测试。
- 涂鸦历史数据主要是 PNG/Data URL；PencilKit 可读取为背景预览，但不能恢复为独立可编辑笔画。
- Web `stickies` 当前不在云同步集合中，原生版若要上云必须先扩展服务端并设计删除冲突策略。
- Web API 目前没有增量游标、删除墓碑或 ETag；多设备同时编辑只能继续使用更新时间优先策略。
