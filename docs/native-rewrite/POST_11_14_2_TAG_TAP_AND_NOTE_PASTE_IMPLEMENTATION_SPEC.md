## 1. 考点标签可点选并固定靠左排布

**入口**　编辑／新增错题 → 考点，以截图言语理解 → 逻辑填空 → 错题复盘 → 词义为首要回归场景。`LibraryKnowledgePointTagCollection` 同时服务数量关系、通用考点、旧考点和学习库考点筛选。仅修这个共用组件及其必要调用点，保持属性模型、分组、筛选范围和题型归属。

**原因**　`minimumInteritemSpacing = 6` 是 UIKit `UICollectionViewFlowLayout` 的最小间距，实际一行可能均分余宽。项目另用固定 6 pt 算式提供 SwiftUI 包装高度，绘制与外层尺寸依赖两套排布。点选完全依赖集合视图 `didSelectItemAt`，还把原位拖动的长按识别器放在同一容器。`.id`、组切换和 `toggle` 的源码显示已选集合本身可以直接更新，并无组内点按禁用。当前证据能确认排布问题和尺寸／点按路径的缺口，尚无实机事件证明具体是哪一层拦截了该次触摸。[UIKit 最小项间距](https://developer.apple.com/documentation/uikit/uicollectionviewflowlayout/minimuminteritemspacing)

**排布**　用同一套按当前可用宽度计算的行和 item frames 驱动 UIKit 布局与 SwiftUI 高度，替换流布局自动分配余宽的行为。首项贴齐容器左边，按现有顺序自然布局，项目间距和行距均为 6 pt，余量留在右端。保留 12 pt 系统常规字号、左右内边距 10 pt、上下内边距 8 pt、6 pt 圆角、现有灰底和蓝色选中样式。标签宽度按内容，单项超过容器宽度时在自身框内换行并增高。勾号用固定的尾部空间，保证选中和取消时对同一个位置的下一次轻点仍命中。无有效宽度时等待实际布局，宽度变化后使布局缓存失效。每组的集合视图边界与实际内容高度一致，确保组与未分组的点击区域无重叠，超出弹窗可视范围由外层列表滚动。保留约 420 × 468 pt 弹窗和现有窄窗口约束。

**点按与拖动**　在 `KnowledgePointTagCell` 用覆盖整枚标签的原生 `UIButton` 激活，按释放且仍在按钮内时，以当前配置的完整 `LibraryKnowledgePointReference` 发出一次选择事件，移除同一次触摸从 `didSelectItemAt` 再提交的路径。保留原生可访问性按钮、选中状态和操作。轻点更新弹窗本地选中集合、蓝色、勾及计数，再点取消。保留 UIKit 原位长按拖动，沿用 0.35 秒门槛；识别为拖动或滚动的触摸不执行选择，并覆盖长按识别取消控件触摸、拖动结束或取消后恢复点选。重排复用相同的行布局和当前列表数据，避免点击触发重排以及刷新后重复激活。组、搜索和跨题型浏览保留已选草稿，按「确定」才提交引用，按 X 恢复进入前的选择。若复现发现触摸未到达 `UIButton`，沿弹窗覆盖层和实际视图边界定位，在被遮挡的共用入口修正。

**验收**　逻辑填空同一组点同一标签两次，检查 0→1→0 和颜色；跨组、跨题型、搜索及旧考点同时选择，同名不同题型按完整身份独立；确定后保存题目，退出重开验证引用。验证 X、清空、已选状态、仅用筛选的入口、长按拖动和拖动后第一下点按。按真实标签宽度比较横竖、窄窗口与多行长标签，截图所示前两项固定相隔 6 pt，无两端对齐或遮挡。测试快速点按、滚动后点按、长按空白区以及移动失败回退；按原生滚动和拖动路径做实机检查。

## 2. 错题笔记粘贴保留段落间距与格式

**截图与源码证据**　2023 甘肃第 35 题对照图中，复制选区从「错因」后的冒号附近开始，右侧贴入内容从冒号起，故该截图不证明「错因」二字丢失。能看到四段入笔记后几乎挨在一起，前三段之间原有的段落节奏不见了，局部粗体仍在。11.14.2 的 `normalizingPastedNoteParagraphs` 一律把 `lineSpacing` 清零，普通段距只裁剪到 0…4 pt，缺段距直接留 0。`preparedClipboardText` 无表格时优先采用 RTF／RTFD；`finalizedRichPaste` 对同次复制的 HTML 主要取列表、引用，且从非 HTML 主表示导入时没有使用 HTML 标题字号映射，也没有恢复普通段落间距。点完成可走编辑快照，也可重新解析 HTML；`noteHTML` 普通段落零值不显式编码，非零行距被编码为 `fontSize + lineSpacing` 的 CSS 固定行高。HTML 导入可能因此与编辑态不同。按图片无法读出该次剪贴板具体格式，本轮以实机样本与双格式用例验证。11.14.2 已引入的行内正确编码、缩进、附件和文末测高改动作为本轮基线。

**粘贴目标**　错题笔记普通正文 16 pt，延续本应用字号、粗细与颜色。对于带真实段落的富文本粘贴，段内在字体自然行高之外默认增加 2 pt。相邻两个非空的独立普通段，源文缺失正段距时在上一段后留 4 pt，下一段前为 0 pt。来源已经提供显式段距时，合并相邻段间的间距后最多 4 pt，只应用一次；行距可保留合理的非零值，取 0…2 pt，来源固定行高不直接照搬。用户选区里明确存在的空段完整保留，其两侧无自动加段距。段内软换行只有行距，不额外加段距，自然折行不写入换行。引用继续用 12 pt 默认缩进和 5 pt 段距，列表续行对齐正文，同组列表项沿现有紧凑样式，表格单元格使用原规则。手动输入的普通段落、仅有纯文本且无结构的剪贴板沿既有 11.12.4 默认排版，已有笔记中未参与粘贴的段落保留。

**实现**　在 `RichTextTextView.Coordinator.preparedClipboardText`／`finalizedRichPaste` 保留主导入表示里的完整正文、粗体和附件；同一剪贴板项另有 HTML 时，经可靠的一对一段落文本匹配用其语义块结构和适用的间距、字号信息补足 RTF／RTFD，不用长度或同名匹配覆盖正文。只解码本次需要的表示，避免按行反复调用 UIKit 导入。入 `textStorage` 前一次归一来源行高、段落边界与间距。段内插入的首尾合并按目标段样式，独立段落保持此次规整样式。为本 App 新导出的各段写入可精确读回的行距与段前、后距元数据，包括显式零值，并与段落结构配对校验。`LibraryInlineNoteView` 的编辑、刚完成的快照、从存储冷读及草稿恢复采用同一组属性；本版元数据不经过旧 2 pt／5 pt 清理启发式。读回通过 `NSParagraphStyle` 恢复额外行距，不借固定 CSS 行高或插空行近似。保留旧 HTML 读取和原始存储，避免批量重写。异常路径保留用户正文和已保存草稿。

**验收**　按截图从冒号复制到「我还想补充一个很关键的区别」末尾，确认只复制选区范围，检查应有四段、粗体保持在句内、段间可见区分、同段折行更紧。以相同窗口宽度对照粘贴当下、仍在编辑的自动保存、点完成和关闭重开后的段落数、文本、粗体范围、间距属性和视觉排版。用同次 HTML 与 RTF 分别携带、HTML／RTF 单独携带、纯文本、列表、引用、表格和图片各跑一例；用至少 20 段验文末可滚到、无内容丢失，并检查旧笔记能读。必要行为验证要覆盖实际新增布局及段落属性往返，发布归档不作为实机验收。
