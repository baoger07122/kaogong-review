# 历史错题发热与耗电排查

基准为已发布的 11.17.2（151），源码 `28eba05410b7ac251a4f9d64ecf8cb6f1199745f`。现象是查看历史错题时 iPad 发热并降低亮度。以下保留当时的源码诊断和实现规格；本轮已按规格实施，目标版本为 11.17.3（152）。当前仍没有当时的能耗轨迹、温控状态或 CPU 调用栈。Apple 确认温度升高时系统可以主动降低显示亮度，但具体设备的降亮原因及 App 耗电占比需实测。项目源码未发现直接设置系统屏幕亮度的应用代码。[Apple 温度保护说明](https://support.apple.com/zh-cn/118431)

## 01 学习库只读详情提前建立编辑数据

- **入口与事实**　学习库打开一条普通错题详情，或在详情中横向切题。即使未点「编辑」，`LibraryRecordDetailView` 也会在加载当前题目时调用 `prepareEditorDraftIfNeeded`，出现回调另外还会尝试一次。准备工作会在主线程构建 `LibraryRecordDraft`；上层以题目 ID 把完整草稿放入 `preparedEditDrafts`。草稿包含原始 payload 与解析对象，部分历史记录含题图、选项图及长笔记。详情中横向翻页只换当前题目 ID，导航路径不变，因此这一轮翻过的草稿可能在返回列表前一起留在内存。两处调用有当前载入校验，单次进入实际是否构建两遍取决于时序。
- **拟改动**　只读详情和相邻预览只准备当前展示数据。由用户点「编辑」或确有编辑操作时构建完整草稿，用已加载的当前题版本复用原始对象。最多保留当前编辑请求的准备结果，切题、取消、返回或记录版本变化时失效。旧数据兼容和保存前版本保护照常应用。
- **验收**　从学习库进入详情并连续横滑，只读链路的完整草稿构建次数应为 0。打开编辑后验证题干、图片、考点及笔记完整，取消再切题没有串数据。用带大图的旧数据检查多次翻页后的草稿占用不会继续累积。

## 02 笔记在只读详情进行全量校验与渲染

- **入口与事实**　`LibraryInlineNoteView` 随详情挂载。页面出现会用 `LibraryInlineNoteSaveService.versionKey` 对整条题目 payload 做 SHA-256，并尝试读取恢复草稿。共享的 `recordStates` 会保留确认状态及原始 `Data`，当前未见已完成题目的状态回收。题目已保存且没有旧草稿时，会走检查和渲染；已有未写入草稿时，恢复逻辑还可能重新入队保存。
- **排版开销**　有正文时，`prepareNote` 在主线程导入富文本、处理附件和段落并准备可编辑副本。回退路径虽将一段解析交给后台，附件、属性和部分段落样式仍回到主线程组装。普通阅读会承担一部分编辑准备成本。详情查看正文、小计记录及实际保存是不同链路，现有证据无法断言每次只读查看都在写盘。
- **拟改动**　以题目标识、版本及当前笔记内容复用已完成的显示结果，在现有滚动页中按接近可见区或交互需求准备重附件。编辑快照和全 payload 校验按编辑、写入或确有旧草稿恢复的需要执行。待保存、失败和恢复中的会话继续保留原始数据及保护措施；已确认且无任务的条目只保留轻量版本信息或有界缓存，减少同一状态重复发布。旧草稿检查按记录版本合并，失败保持可恢复内容，避免反复自动写。
- **验收**　分别打开空笔记、纯文字、长文、表格与照片样本，记录摘要计算、渲染和草稿读取次数。只读空笔记不启动编辑准备，离开后纯展示任务不再更新页面。恢复未保存旧草稿、版本冲突、正文复制、实际编辑保存均用原数据校验。

## 03 快速翻题时的解码、图片与预览

- **已确认**　详情 `loadActivePayload` 和相邻预览 `LibraryRecordSwipePreview.loadPreview` 启动独立的 `Task.detached` 解码 JSON，只在返回结果时检查外层取消。迅速翻走时已经开跑的解码不会随页面自动停止，短时间可能和新题的任务重叠。相邻预览优先用索引，无索引的旧题会读原 payload。题图另走 `LibraryImageLoader`，已有缓存、合并请求和并发限制，不能归为无上限同时解图。详情仍在拿到图片时更新画面，挂载时还会增加任务键的出现代数，需核对是否导致同一图重复请求。
- **拟改动**　当前题解码优先，相邻预览用轻量数据。对按记录及版本的短时请求合并，显示任务退出时传递取消，在开始和可中断阶段检查。Swift 的单次 JSON 解码不一定能立刻停，避免它在尚未开始时继续排队。图片区分实际显示尺寸和缓存版本，避免无意义的重新提交，保留已有缩略图加载、旧图片兼容及编辑读全图通路。
- **验收**　连续翻复杂题，覆盖同题返回、取消半次滑动、有无索引和图题场景，测解码启动数、相同资源请求数、并发任务和离开后的残留。核对图片、题干、答案和笔记随题目正确更新。

## 04 复习入口与静置阶段分别检验

- **若走「复习」**　`ReviewView.queue` 每次读取会过滤并重建整份题池的 ID 字典，同一题界面显示索引、总数和当前题时可调用多次。普通复习题界面还会直接读 `record.jsonObject`。概览汇总后半段在后台，收集记录与映射结果仍占主线程。拟按复盘来源、题池版本与会话队列变化复用映射，题面复用当前记录的展示数据，保留答题后复习记录写入。分别验证概览、切题、答题和恢复会话。
- **若在普通详情静置也持续活动**　检查 App 根导航首帧 `CADisplayLink` 及后台任务。源码确认探针会在未附着窗口时创建回调，回调遇到窗口为空会返回且不会在该分支自行失效。若探针最终未挂载或没走清理，按显示刷新节奏的回调可能持续。需用时间线确认该风险是否在这次发生。仍在读取时若看到 Home 的秒级待办刷新出现在轨迹，也检查相应页面是否处于活跃状态。按证据修复探针的挂载、消失和失败生命周期，避免常驻刷新。验收以停止翻题、返回列表及切到后台后的回调和任务数量为准。[Apple CADisplayLink 说明](https://developer.apple.com/documentation/quartzcore/cadisplaylink)

## 测量与验收

- 用同一台 iPad、相近起始温度和亮度、同一数据集，分别记录「进入学习库错题列表」「只开一道纯文字题并静置」「连续翻含大图、表格和长笔记的题」「回列表静置」「复习入口」等阶段。每个阶段记发生时间、是否充电和加载状态，用几次短会话比较，避免用单次温度感受判断优化效果。
- 用 Power Profiler 获取 App 电力影响、系统热状态、显示亮度及充电状态，用 Time Profiler、SwiftUI 轨迹和现有日志对齐编辑草稿构建、整条 payload 校验、富文本排版、JSON 解码、图像请求和后台工作。若切题后任务很快结束、静置功耗仍高，继续查逐帧回调和持续更新。若仅连续翻题时升高，优先减掉只读阶段的重复工作和缩短旧任务寿命。记录活跃与空闲基线、同样操作的前后对照及实机未覆盖的情形。[Apple Power Profiler 操作说明](https://developer.apple.com/documentation/xcode/measuring-your-app-s-power-use-with-power-profiler)

## 交付记录

- 本轮已移除只读详情进入及切题时提前构建完整编辑草稿的调用；用户发起编辑时仍按当前记录创建草稿，并保留原始 payload 与版本冲突保护。
- 只读笔记使用轻量版本标识，不把完整 payload 留在确认态；完整 SHA 校验及 payload 捕获留到实际编辑／写入。普通富文本阅读不再保留一份编辑属性副本；安全回退模式仍只允许在可安全编辑的条件下进入编辑。已确认且空闲的保存状态在视图离开时回收。
- 详情和相邻预览改为共享按记录版本合并的 JSON 解码任务，任务取消后无等待者时取消未开始或仍可取消的工作。详情图片加载不再因每次重新出现而改变任务键；保留已有图片请求合并与缓存。
- 主导航帧探针仅对已挂载、可见页面创建显示链接；无效状态下清理链接。复习队列按题目版本复用 ID 映射。
- 本地源码差异核对及 `git diff --check` 通过。最终 CI run **#388 / 44011060283** 在提交 `2014a0aa35d71c6fb5327eecc8f8726a831728ea` 上成功：领域行为检查、Xcode 真机目标归档、dSYM UUID、App 资源/version 检查、IPA 打包和上传均通过。模拟器检查按推送工作流配置跳过。
