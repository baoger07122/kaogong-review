# 题型管理与每日待办的原生拖动排序

## 1. 图形推理题型管理

- **入口和现状。** 设置 → 题型管理 → 判断推理 → 图形推理。题型行当前用上下箭头逐项移动。其他通过同一个模块题型管理页进入的科目也使用这一套操作。
- **交互。** 「题型」标题行加入蓝色「调整顺序」，进入后改成「完成排序」。用与考点排序相同的 SwiftUI `List`、`EditMode` 和 `onMove` 显示行尾系统拖动手柄。在当前页面切换模式。排序时暂停新增、重命名和删除操作，结束后恢复，少于两项时禁用入口。
- **版式。** 沿用原来的普通正文 14 pt、44 pt 行最低高度、20 pt 外边距、14 pt 行左右内边距、白底及分隔线。沿用现有大尺寸面板，排序前后列表同宽、同高、左对齐。长题型名在可用宽度内换行，排序手柄保留在右侧。窄分屏继续适配面板宽度。
- **保存。** 每次放下时将可见行下标映射到题型 ID，按新顺序保存到当前科目、模块。当前记录 ID 顺序与该次拖动起点不符时提示重试。排序沿用原来的保存错误提示。「完成排序」只退出排序模式。
- **验收。** 在图形推理中将「六面体」拖到「平面图形」前，退出后重新进入，核对题型管理与错题编辑选择器顺序。确认面板、左对齐和分栏宽度稳定，单项时无手柄，普通模式下可以新增、重命名及删除。

## 2. 每日待办管理

- **入口和现状。** 首页 → 今日待办旁的每日待办按钮 → 管理次序。截图里弹窗尺寸未变，变窄的是里面的灰色待办卡片。源码切换到了按内容估算尺寸的自定宽集合项，未给项指定列表全宽。
- **交互和版式。** 保留「管理次序／完成排序」，在同一个普通 SwiftUI 列表打开系统编辑模式。卡片背景跟随列表行全宽，右侧用系统手柄接替暂停／恢复和删除控件。沿用弹窗最大 440 × 620 pt、20 pt 内边距、卡片原有 13 pt 圆角、12 pt 内容内边距及 8 pt 行间距。标题沿用 14 pt 中等字重，副标题沿用 11 pt，窄窗口按相同边距收缩，长列表可继续滚动。
- **保存。** 放下时按每日待办规则 ID 调用现有排序事务，事务会校验规则集合并保存序号，失败走原错误提示。排序仅调整规则及今日循环待办的既有显示顺序。
- **验收。** 打开有多项的每日待办，对比排序前后卡片左右边缘与行高。拖动一项跨多行，退出并重新打开，核对顺序及首页今日待办同步。同样检查窄分屏、长列表滚动和切回普通模式后暂停、编辑、删除可用。

截图作为原尺寸参照，系统手柄沿用应用内考点排序交互。收到「发布执行」后交 Luna 构建。
