# 错题保存返回与笔记输入整改

## 保存错题和返回详情

- 入口为行测错题详情进入编辑，也覆盖首页、套卷关联等复用同一详情与编辑器的入口。录像中编辑保存至开始返回约 2.7 秒，返回后至新标签和工具栏可用约 3.6 秒。
- 编辑草稿记录初始化时是否成功读出原始 JSON。保存从草稿中复用已读数据，保存前和提交事务内继续对比原记录字节及版本。损坏数据、并发更新、关联错题／词语／笔记及恢复草稿沿用既有处理。整理载荷与索引继续在后台完成，由 SwiftData 事务统一写入。单独记录保存准备、事务与交接用时。
- 事务成功后，把本次已解析的完整错题记录交给详情。用题目标识、版本和完整载荷校验，只匹配同一成功提交；缓存只保留最新一条编辑提交。返回时直接显示新内容和工具。图片仍用既有大小和样式；同一图片使用原缓存标识，替换图使用新标识。外部更新、切题和失败维持现有防护。保存按钮的文案、位置和视觉样式沿用原组件。
- 验收：修改一个标签、修改题干或图片、无修改保存，分别核对按钮松手到返回与返回到可操作时间。返回第一屏显示新标签，马上打开菜单再编辑，检查最新记录和图片。另测从列表翻到相邻题后编辑、并发覆盖保护以及带关联的题目。

## 错题笔记的表格

- 正文与当前单元格作为原生宿主中的两个同级 UIKit 输入视图。键盘只交给当前输入视图，进格时正文失去焦点不触发整篇发布。中文组字期间保留系统标记文本和候选，显式完成或切格时提交一次；输入真实的重复字母原样保留。
- 系统键盘上、下箭头切到同列的相邻行，键盘附件的现有上、下按钮使用相同规则。横向键在格内沿用原生光标行为。目标格光标落到末尾，可继续输入。边界留在当前格，输入法有候选时保留原生箭头。不调整表格字号、线条、宽度或窄窗排版。
- 验收：用拼音键盘点空格、按一次 `c`，候选前只出现一个字母，再输入汉字。重复输入两个相同字母仍保留两个。连续在同列上下切换并输入，保存重开校对每格，最后一行及候选状态不误切格。用浮动和外接键盘分别检查。

## 错题笔记的引用和按点定位

- 编辑及阅读模式都在左边绘制 3 pt 系统灰竖线，正文左缩进至少 14 pt，随文字换行。去除引用中的灰色底纹并保留有色高亮。Markdown `>` 与现有 HTML `blockquote` 保留同一引用语义，正文、字体、字号和编辑器其他格式沿用现有规则。
- 手指单击正文，用实际按点和 TextKit 字符位置定位。初次打开编辑及从表格回到正文时先转焦点再落光标。单击不抢候选词、拖选、长按或双击选词。延后执行的定位必须来自当前编辑会话，且期间未输入新内容。滚动只用于把被键盘挡住的光标移进可见区域。
- 验收：先点正文中部进入编辑，插入一个字校对位置，再点另一行及表格外的正文检查单次定位。检查长按选词、双击、键盘避让及没有正文的空笔记。用工具栏设置引用或粘贴多行 Markdown 引用，检查编辑、保存后和重开都显示竖线，无灰底。

新增用例覆盖事务提交后取得同版本详情、过期编辑保护、引用灰底和高亮分离，以及单击定位与表格上下切换后追加文本。系统拼音键盘候选和外接键盘另做 iPad 交互验收。
