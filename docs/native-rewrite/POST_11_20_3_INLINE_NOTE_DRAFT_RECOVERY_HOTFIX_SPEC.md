# 错题笔记恢复草稿按钮失效热修

## 入口与已确认原因

行测错题详情 → 错题笔记 → 本地恢复草稿。已发布的 11.20.3 包含停止富文本预览重入的修复。截图中的黄色文案和红色文案同时出现：草稿只有只读预览，页面却要求继续编辑再点「完成」。

- `LibraryInlineNoteView.manualDraftActions` 显示「继续编辑」文案，随后在 `editableAttributedText` 为空时禁用。草稿正文也只有存在可编辑快照才装配点按。两处无响应有直接的代码依据。
- `confirmManualDraftRebase()` 只更新保存基准和恢复草稿，随后清掉版本冲突。此时「保留当前内容」入口消失。旧 `discardManualRecoveryDraft()` 也仅接受冲突标志，普通恢复草稿和重设基准后的草稿无法从这条路径丢弃。原删除异步使用 `try?`，失败不提示。
- 恢复预览的严格解析会拒绝不能安全往返的格式，包含现有允许范围以外的样式、链接或附件。具体是哪项在用户这份草稿中触发，现有截图无法分辨。它与草稿内容仍保留、正式笔记未写入可同时成立。

## 目标与界面

沿用现有错题笔记区和安全预览。在「未保存草稿」下按当前状态显示可执行动作。用现有 13 pt semibold 次要操作样式、强调蓝和破坏性红，点击区至少 44 pt，靠左，窄窗折行。保持未保存状态名称及正式正文布局。

1. 有可编辑快照时显示「继续编辑」，按钮与正文点按都打开该草稿，并定位到点击处或文末。保留粗体、自然段、列表和原附件；用户点「完成」时才正式写入。
2. 只有只读预览时，提供「原样恢复」。点开现有样式的确认弹窗，说明将把当前草稿原文保存到这道题，原有排版和附件随原文保存，部分格式可能继续以只读方式预览。取消无写入。确认按钮用「完成」，提交走既有版本校验和正式写入回执，使用未截断的原始草稿 HTML。安全预览、截断文本和重渲染结果均不可作为提交源。失败保留草稿并显示原因。原样恢复覆盖常规编辑仍无法识别的旧格式，隐藏不可用的继续编辑入口。
3. 有未保存草稿时始终提供「丢弃草稿」，包括版本冲突、重新设基准和普通恢复状态。点开确认，说明仅丢弃本题这份本地草稿，确认后移除匹配的草稿版本与待恢复状态，再显示正式笔记。失败时留在当前页面，提示错误并可重试。取消确认弹窗继续保留草稿。
4. 有版本冲突时保留当前正式稿和恢复稿预览。继续编辑或原样恢复前明确当前版本基准，之后按当前可用动作显示提示。采用草稿的选择仅解除冲突，直到点「完成」才正式写入。冲突解除后仍能丢弃草稿。错误和中间状态均可返回或重试，避免显示无法执行的操作提示。

## 实现边界

- 用真实的本地草稿身份、当前记录 ID、记录版本、编辑会话和草稿版本保护恢复、完成和丢弃。先成功落盘或删除，再更新相应成功 UI。保存失败保留草稿，丢弃范围受版本保护。严格校验当前活跃错题，沿用 `LibraryInlineNoteSaveService` 的正式写入和草稿版本栅栏。
- 恢复常见的 App 自身导出或粘贴后的富文本编辑能力。重点验证中文多段落、标题、粗体、列表和原生图片。受限解析可补充已能正确重建的语义，继续校验内容完整性。原样恢复是无法安全编辑的退路。预览与恢复仍走无同步 HTML/WebKit 导入路径，继续手动保存。
- 范围仅行测详情的显式保存与恢复流程。以 11.20.3 已发布版本为基线，核对最新提交、版本后用后续热修版本归档一次，保留已发布 IPA。下版词语清单独立留档。

## 验收

1. 复现截图中的旧版本冲突和只读草稿。接受当前版本后，能看到并操作「原样恢复」和「丢弃草稿」，提示与按钮一致。原样恢复完成后重开比对原始内容和附件。
2. 常规富文本草稿能点正文或「继续编辑」。连续输入、换行、点「完成」、保存失败重试，核对草稿和正式笔记，且不会自动保存。
3. 分别从冲突、重设基准及普通草稿状态执行丢弃。取消仍可恢复，确认后保留正式内容，重开不再出现同一草稿。验证写入失败和较新的草稿版本时的提示、保护与重试。
4. 其他题能独立打开。同题往返、左右翻页、长内容和 iPad 分屏再次核对。发布采用真机目标归档，云端模拟器跳过。交付记录标记设备上的未验证行为。

## 补充一：题型移到详情标题旁

**现有行为。** `LibraryRecordDetailView` 在 `reviewContent(metadata)` 内以独立行渲染已保存题型，因此「题型：错题复盘」出现在题干上方。主标题通过 `detailNavigationTitle` 单独呈现。

**目标与落点。** 在行测错题详情的导航标题区，主标题右侧同一行显示实际保存的题型／错误类型名称。截图示例为「中心理解题　错题复盘」。由同一个导航栏居中标题项目承载主标题和类型，放在「看」及涂鸦按钮之前。维持原主标题的 17 pt semibold 和前导返回位置，类型为 11 pt medium 的次要色文字或复用现有浅色类型标签，间距 8 pt。标签仅显示名称，旁白读出类别。移除题干上方的已保存题型重复行，保留错题和掌握状态位置。窄分屏先截断次要类型名称，让标题和按钮保持可读可靠。当前题未分类、类型删除、载入中或失败时仅显示主标题。沿用刷题模式现有揭示时机。

**数据与验收。** 用已有索引或当前题已加载的载荷解析类型，并校验当前记录 ID，避免在导航标题每次更新时同步解码整题图片数据。数量关系沿用现有模块映射，其他科目沿用题型 ID／目录逻辑。用截图的「中心理解题／错题复盘」、资料分析错误类型、数量题型、未分类和快速翻页验证标题同列、正文无重复、按钮和加载状态正常。

## 补充二：默认隐藏没有实际草稿的提示

**现有行为。** `LibraryInlineNoteView.shouldShowPendingDraftDisplay` 同时用 `hasPendingDraft` 和任意 `errorMessage` 控制整块「未保存草稿」。截图右侧「已保存」与黄色「未保存草稿」同时出现，按现有判断可由仅有错误消息而没有有效草稿解释。显式保存模式还会在页面没有进入编辑时响应场景变更，尝试取得编辑快照，取不到就可能产生此类错误；截图不足以确认具体是哪条错误触发。

**目标与落点。** 初次打开无正文、无真实草稿的错题，显示原「错题笔记」及「点击添加错题笔记」入口，默认不显示黄色「未保存草稿」和任何保存状态。已有正式笔记可正常阅读、点按。只在核实本题确有未提交内容时显示黄色提示与草稿操作，包含此前实际留下的草稿和清空既有正文的待保存改动。读取异常、编辑器尚未建立、附件或存储错误单独处理，不能仅凭错误消息占用草稿区域、遮住正常编辑入口或制造「已保存／未保存草稿」冲突。未进入编辑时跳过场景变更中的编辑快照读取。用实际草稿与正式保存状态统一衍生标志；未开始编辑不能生成空白草稿。已有真实恢复草稿继续可见并沿用上节的操作。

**验收。** 首次打开截图对应的未编辑空笔记及其他无草稿题，切后台再进入，核对无草稿提示且能点进编辑。对比真正有草稿、清空正文未保存、保存失败、丢弃后以及保存成功的状态，提示正确且不串题。仍只在「完成」时正式保存。

## 补充三：标签展示改为居中弹窗

**入口与现有行为。** 首页 →「标签管理」→ 选择科目、模块、题型 →「标签展示」。`KnowledgePointManagerView` 用 `.sheet` 展示 `LibraryTagDisplaySettingsSheet`，视图设置 medium／large 吸附高度和底部拖动条。

**界面与实现。** 接入标签管理页现有居中覆盖层，复用与「选择考点」相同的 `NativeEditorDialog`／`NativeModalContainer`。首选 420 × 420 pt，以当前窗口可用宽高收缩并居中，沿用系统材质遮罩、20 pt 内边距、17 pt semibold 标题「标签展示」、30 pt 圆形关闭按钮和蓝色「完成」按钮。凭关闭 × 或「完成」结束当前弹窗。去掉原底部弹层的拖动把手。正文内部可纵向滚动，标题和关闭操作在 iPad 窄分屏保持可触达。

**内容与状态。** 依次展示当前范围、「错题属性」的眼睛按钮及「卡片顶部」的独立勾选。沿用现有 14 pt 行文字、主次色、至少 44 pt 点击区和设置保存逻辑。保留既有即时保存及失败提示，关闭按钮只收起弹窗。弹窗作用域取当前科目、模块及题型，关闭后继续保留管理页选项及列表位置。背景遮罩阻止点击下层。与新增、分组等现有弹窗使用同一呈现层，避免重叠。

**验收。** 在全屏和 iPad 窄分屏进入标签管理，打开「标签展示」核对居中、关闭和内部滚动。分别改小眼睛和卡片顶部两类标签，重开验证保存。切换其他题型检查隔离。检查标签管理的新增及分组弹窗仍能正常打开。

## 补充四：编辑题目的提示找不到「完成」

**入口与原因。** 行测错题详情 →「…」→ 编辑题目。`LibraryRecordDetailView.requestEdit()` 只要读取到 `noteSession.hasPendingChanges`，就提示点笔记右上角的「完成」。该标志同时覆盖正在恢复、草稿预览和笔记编辑。`LibraryInlineNoteView` 只在编辑状态显示「完成」。用户截图处于未保存草稿预览，无法按提示操作。

**目标。** 无草稿且未编辑时直接打开题目编辑。正在读取恢复草稿时按实际状态等待并重新校验当前题，避免在无草稿时拦住。编辑中的笔记仍通过原右上角「完成」手动保存。草稿预览时用现有系统弹窗提示「请先处理这道题的笔记草稿」，提供「处理草稿」「取消」；主按钮带到当前题的恢复区，按已定义的「继续编辑」「原样恢复」「丢弃草稿」操作。只读草稿的「完成」位于原样恢复确认中。窄窗口和已滚动时均可触达。响应编辑请求不提交或丢弃草稿，保留记录和会话校验及刷题信息揭示规则。

**验收。** 对没有草稿、读取中、正在编辑、可编辑草稿和只读草稿分别点编辑题目。核对提示与屏幕动作一致。保存或确认丢弃后重新打开题目编辑；失败或切题时保留正确草稿。

## 补充五：打开错题省去短时加载页

**入口与现状。** 从行测错题卡片、历史列表、从关联错题进入详情或左右翻题。用户确认问题是进入时能看到单独的「正在加载题目…」页面。11.20.2 已有该加载视图，但同一记录按记录 ID 判定能继续显示。11.20.3 加入请求状态和防止一直转圈的超时保护，`LibraryRecordDetailView.isPayloadLoading` 对冷启动的 .idle、.loading 及版本键不一致立即让加载提示占满详情区。即使能很快读到正文，也会先切到这个中间画面。同题版本更严格可让正文刷新时也被替换；用户这次重点是普通进入时出现该页。

**目标与落点。** 将题干可展示状态与完整载荷待校验状态分开。在 `LibraryView`／活动页路由已有可校验的同题同版本正文快照时，直接作为详情首屏复用。仅有轻量题目数据时，可在详情原位先显示确认属于本题的题干／选项，按需补齐图片和其他数据；缺一部分时只在对应区域保留占位。避免为准备首屏同步解码大图 JSON，也不预取整库。短时冷读取不切到单独的全页「正在加载题目」界面，沿用详情框架；确实慢时在正文位置显示小型局部加载提示，正常读取的首屏及窄窗布局继续沿用现有详情。后台刷新同一题可保留该题已加载正文，后续写操作仍需要最新有效版本。返回、看／刷切换、菜单、笔记操作和保存后处理不得触发无谓的详情重载，特别检查同题本地更新交接。

**保护。** 保留 11.20.3 的请求身份、版本校验、过期结果隔离、取消以及明确的失败和「重试」。首次进入无有效数据时不能显示别题缓存，也不能把部分内容当作已校验完整载荷供编辑、判分、笔记或保存。继续按现有看／刷规则展示内容；不为改善首帧提前暴露答案。旧图题、题库关联记录的数据缺失和慢载入保持可恢复。

**验收。** 普通短题和历史图推分别首次点击、返回重进、单条和左右翻页，检查普通读取不出现独立的加载页、不同题内容不会混用。测试切换看／刷、开菜单、处理笔记及同一条记录保存后正文不闪白。用真正慢读和读取失败用例核对局部提示、超时、重试与返回，保持快速键入和手动保存的现有流程。
