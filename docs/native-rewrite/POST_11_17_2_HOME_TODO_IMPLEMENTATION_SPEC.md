# 首页待办整改规格

基准为 11.17.2（151）和本轮首页截图。以下是当时的实现规格；本轮已按规格实施，目标版本为 11.17.3（152）。UI 交互验收、构建和发布状态记录在文末。

## 01 今日待办左对齐与自适应行高

- **入口与原因**　首页「今日待办」的 `HomeTodoRow`。标题和备注虽在左对齐的 `VStack` 中，外层却把这一组以 `.center` 对齐到占满可用宽度的框内。行内容自身最小高度 44 pt，再叠加上下各 10 pt 的内边距，空备注也至少占 64 pt。右侧日期分行与秒表还能进一步挤占空间。备注目前会去掉首尾空白，空备注文字行已经隐藏。
- **布局**　保留白底卡片、18 pt 外圆角、原 0.6 pt 分隔线和浅蓝科目徽标。行内依次为完成圆圈、26 × 26 pt 科目徽标、左对齐内容区。沿用 10 pt 横向间距和 14 pt 常规标题，未完成用主文字色、已完成用次要文字色。年月日 10 pt 中字重、次要文字色，与标题同一行，紧随标题，间距 8 pt。所有标题从相同左边缘开始。备注放在同一左边缘的下一行，12 pt 常规、次要文字色，段前 3 pt。
- **行高与窄窗**　整体最小高度 44 pt，上下各 6 pt 内边距放在行内，触控区域覆盖整行对应操作。无备注或只有空白字符时按单行紧凑布局。有效备注按内容增高，预览最多两行，点击正文可编辑完整内容。窄窗口常规字号下日期保留完整一行，标题过长用尾部省略，完整标题由编辑页及 VoiceOver 提供。辅助字体放大时允许内容增高，保留可读性。保留直接点正文编辑、点圆圈切换完成和原生左滑按钮。
- **实现与验收**　修改 `HomeTodoRow` 与 `HomeTodoCollection`，以 UIKit 实际布局后的高度为准。首屏尺寸查询只读缓存或预估，沿用 11.17.2 的异步高度通知。用截图同类任务建立空备注、纯空白备注、单行备注、多行备注各一条，核对左边缘、行高、长标题和分屏显示。带已有待办冷启动，验证首页列表不会因本轮改高度再次触发布局中止。

## 02 待办取消计时与时分展示

- **入口与原因**　首页行内的 00:00:00 和播放／暂停键来自 `HomeTodoRow`，每行有秒级 `TimelineView`。首页统计卡有正在运行的计时胶囊。首页新增／编辑、每日待办新增／编辑都有「计划时间」输入。每日待办规则卡显示「每天 HH:mm」，「待办统计」汇总还有「学习分钟」。
- **目标与文案**　首页行内移除秒表和播放／暂停键，首页统计卡移除运行中的计时胶囊。一次性待办只选「计划日期」，每日待办只选「开始日期」。日期统一为 `2026年11月17日` 形式。普通待办显示计划日，循环实例显示当天发生日，已完成项显示完成日，旧记录无完成时间时回退到原计划日。每日待办规则显示「科目 · 年月日开始」，保留暂停标识。「待办统计」去掉「学习分钟」，保留日历、每日明细及「本期完成」，完成数卡可用整行宽度。此日期展示规则同时适用于历史待办，避免同一列表采用两套格式。
- **数据与实现**　复用 `HomeRecordRepository.chineseDate` 和现有本地日历规则。用 `scheduledAt`、`dailyDate`、`completedAt`、`startDate` 分别表达计划日、发生日、完成日和循环开始日。新建只按所选日期保存，日级生成和去重沿用规则 ID 与本地日期。现有含时分字段仍可读，编辑备注或标题不批量重写历史时间。停用待办计时启动与续算入口，保留旧的已记录用时；升级时若有正在计时的旧项，用现有停止规则收尾一次，循环实例至多结算到其当天结束。处理可重试且不重复记时，失败不拦首页。工作范围为待办功能，速算等独立计时功能继续使用各自逻辑。
- **验收**　从首页、每日待办和日期明细各新建一项，保存、重开、跨午夜后核对年月日和循环实例数。升级一组含晚于当天当前时刻的旧计划、旧完成记录与旧活动计时的样本，确认既有日期及完成记录可读，页面无时分、秒表、计时按钮或学习分钟汇总。

## 03 左滑删除与每日规则的整组删除

- **已确认**　`HomeTodoCollection` 关闭了全滑直接执行。左滑只是露出按钮。当前循环项点「仅删除今天」仍要到 `HomeView` 再确认，且首页还暴露了删除每日规则入口。所有左滑动作都先按固定的 `completion(true)` 向 UIKit 报成功，普通删除写入报错、查不到记录或者循环项仍在等用户确认时，也会关闭左滑。普通删除依赖视图传来的记录快照，找不到 ID 就静默返回。循环删除在日期、实例或状态不符时也可静默返回，而调用方仍会提示成功。成功写入 `isDeletedForDay` 的循环实例会被首页和待办统计过滤，同 ID 的删除标记还会阻止当天重新生成。当前缺少操作录像或设备数据，无法判断用户遇到的是未完成确认、写入失败、旧视图未刷新，还是其他路径。
- **首页操作**　一次性事项左滑展示红色「删除」，点按钮删除该记录。循环实例的红色删除动作统一为「删除今天」，点一次只提交该实例的当天删除标记，随后从首页、当天统计明细和相应计数消失。左滑继续只露出按钮。保留原「跳过今天／恢复今天」作为单独的非删除动作。展开的已完成区也按同一范围处理。首页左滑、菜单、VoiceOver 动作都移除整组删除入口。
- **整组操作**　仅在「每日待办」管理页的规则垃圾桶进入。拟采用「删除整组待办」二次确认，正文明确写出会停止今后生成，并删除该规则关联的所有日期记录，包括历史及已完成项。取消不写入。这里将用户的「删除全部的记录」理解为连同历史实例一起处理。按规则 ID 查询和事务写入，只删除能明确关联到该规则的实例与规则本身，重名普通事项和其他规则的记录都不受影响。旧记录无可靠归属时保留。
- **实现与失败处理**　复用 `HomeRecordRepository`，普通删除按稳定 ID 查最新对象，循环删除同时复核规则和日期，防止跨午夜误操作。日期或目标已变化时提示刷新；已确实删除的重复请求按幂等结果处理。事务完成后再向 UIKit 报成功，并基于保存结果刷新唯一同源的列表和计数。失败仅报失败、保留行并提供重试，不提示已删除。当天的删除标记继续参与生成去重；检查旧数据是否存在同规则同一天的多个实例，若确有重复，只处理身份和发生日都可证实的项。
- **验收**　普通事项点删除后立刻消失，退出重开与从待办统计日期明细查找仍无此项。循环项点「删除今天」后，前后台切换、重启、暂停恢复规则后同日不重生，第二天恢复自动生成而历史仍在。用两个同名规则及一条同名普通事项确认整组删除仅在管理页可触发且只删除指定规则。模拟保存失败、目标在动作期间已变化，用界面反馈和数据库状态核对，尤其检查失败时是否误报成功。

## 04 已完成待办默认折叠

- **入口与现状**　首页「今日待办」目前给 `HomeTodoCollection` 传同一数组，已完成项只在排序中排到后面。
- **目标**　未完成列表底部，有已完成事项时才出现「已完成（N）」折叠行。入口为 44 pt 最小高，12 pt 中字重、次要文字色、左对齐，右侧系统箭头表示展开状态。初次进入首页及重启默认折叠。同一次首页停留期间按用户手动状态保留，勾选完成不会自动展开。展开后显示与上方相同的紧凑行；取消完成立即返回上方。全完成时仅保留进度和折叠入口；无已完成项时不显示该入口。略过项按现行规则留在未完成区域，已删除项两边都无。
- **实现与验收**　在 `HomeView` 用同一份有效待办按 `isCompleted` 分出两组，保留现有未完成、进度、已完成计数口径。复用行组件与 11.17.2 的非重入高度策略。操作未完成→完成、完成→未完成、删除、全部完成、折叠／展开和重启，核对各处计数、滚动和语音提示。统计页按日期展示完整记录，首页折叠状态不用于筛选历史明细。

## 交付记录

- 首页待办标题与完整年月日并排、左对齐；标题尾部省略，备注最多两行。默认字号为标题 14 pt、日期 10 pt、备注 12 pt，并使用缩放字号支持辅助字体放大。空备注行维持 44 pt 最小行高，非空备注随内容增高；保留现有 UIKit 异步测量及非重入更新策略。
- 移除了首页行内及统计卡上的秒级计时显示和控制，也移除了待办表单的时间选择；保留已有耗时历史字段。首次首页任务会一次性停止遗留的运行中计时器并保留已累计时长。新建待办使用所选日期的零点，编辑既有记录时保留原记录的隐藏时分秒；界面只展示日期。规则列表也不展示时分。
- 「学习分钟」统计已移除；已完成任务默认收起，仅在当前首页会话中记住用户展开状态。按真实完成日期显示，旧完成记录缺少时间时回退到计划日。
- 普通待办左滑按最新记录 ID 删除；循环实例左滑「删除今天」只写入当天隐藏标记。整组删除仅从每日规则管理页进入确认，事务按 `dailyRuleID` 删除规则及可明确归属的全部历史/已完成实例；同名但未关联的待办不会被匹配。删除与跳过操作的 UIKit 完成状态取决于持久化结果，错误时保留数据行并显示错误。
- 源码差异核对及 `git diff --check` 已通过。代码编译与工作流强制的领域行为检查待 IPA 工作流执行；该推送工作流不运行模拟器交互测试。首页冷启动、左滑失败/成功、日期统计及动态字体仍需实机交互确认。
