# 主导航切换卡顿排查与整改规格

基准为已发布的 11.17.2（151），源码 `28eba05410b7ac251a4f9d64ecf8cb6f1199745f`。对照 11.14.3（149）及 11.17.1（150）。以下保留当时的主导航诊断和实现规格；本轮已按规格实施，目标版本为 11.17.3（152）。当前仍没有本次 iPad 切换的逐帧记录及主线程调用栈。

## 01 进入学习库时重复读取考点目录

- **入口与现状**　底部「学习库」，包括首次点入、返回已有学习库页面和保留了考点筛选的场景。11.17.1 新增了 `LibraryView.knowledgePointNames(for:)`。学习库构建首批卡片时，默认最多 40 条，逐条先执行这项计算，再进入 `LibrarySnapshotCache.snapshot` 检查命中。相同模块的多道错题会反复查同一批目录，即使卡片已有可复用快照。
- **已确认的开销**　逐条读取题目的索引字段，通过记录数组查找目录键并解析旧考点目录；言语理解和资料分析还会读取错误类型目录，每个可用类型再次读取同科目的考点库。目录明细经 `StoredRecord.jsonObject` 重新解码。学科侧栏计数、待确认来源计数和排序也会遍历记录。选了考点或设置搜索条件时，其他路径还可能对整批候选做同类工作。源码证明这些工作处在页面生成路径且会重复，尚不知道在用户 iPad 上各占多少时间或影响哪些切换帧。
- **拟改动**　改 `LibraryView`、`LibrarySnapshotCache` 和考点库读取接口。用同一数据快照一次读取旧目录、各科目错误类型和类型化考点，按规范化科目与模块复用名称集合。优先使用结构化考点字段，只在旧字符串确需识别时取名称集合，同一批卡片、筛选和搜索共享该结果。目录缓存以对应目录记录的版本和实际数据变化为依据，在新增、改名、删除、迁移、导入后失效，保留跨题型同名引用、逗号原名和旧数据兼容。SwiftData 记录只在各自上下文读取，移往后台的处理使用可安全传递的值快照。
- **验收**　在同一数据集下对比首页→学习库的首次与连续往返。至少覆盖同一模块多道错题、有结构化考点、旧逗号考点、跨题型筛选、增删名称后立即回学习库。记录首批快照更新、目录解码次数和主线程耗时，确保同一目录在一次数据版本内复用。侧栏计数和排序只有测到显著影响时再针对性处理。

## 02 首页、复习与设置在切换时的其他工作

- **复习**　`ReviewView.overviewTaskKey` 在「未选中」与「已选中」之间换键。回来会再走复习概览准备，即使数据未变化。概览汇总主体已放后台，但构建记录版本、筛选、抽取输入，以及将结果映射回记录都在主线程。首次进入还可能恢复旧会话。拟按数据变化、复盘来源和到期日复用现有概览，必要时后台计算，并拦截离开后的旧结果。验收连续往返、跨天、切换来源及改一条题后回到复习，检查统计更新和会话恢复。
- **首页**　`HomeView` 在同次页面生成过程中多次访问 `todayTodos`，会重复解码、排序和重排待办；活跃任务会检查当天循环实例。11.17.2 的 `HomeTodoCollection` 允许先估高，在正常布局后再异步更新。它可能影响「回首页」时的第二次布局，暂未证实造成掉帧。拟先看返回时是否重复生成快照或高度更新，再按当前日期及记录版本归并；保留 11.17.2 的异步测量，避免重引发启动布局重入。验收有任务、无任务、长备注，以及新增或删除后回来。
- **设置**　`SettingsView` 进入时有一次同步记录总数查询。若设置↔首页也同样卡，测该查询、首页刷新及主导航共用渲染路径。复用已有计数并按实际数据变化刷新，仅在测得同步查询占用明显时执行。验收首次进入、反复切换和备份导入后总数正确。

## 03 主导航动画本身与实测

- **已确认**　现行底栏由系统 `TabView` 绘制。11.14.3 到 11.17.2 的 `RootTabView`、选中处理和底栏动画代码没有改动。切换仍会改变当前选中及所有页签探针收到的测量代数，可能引发额外视图更新。现有日志的「first display frame」取自一次 `CADisplayLink` 回调，只能提供近似的点按到回调时间，无法判断动画中段持续掉帧或 GPU 合成耗时。
- **验证顺序**　同一台 iPad、相同数据与窗口大小，对比首页↔学习库、首页↔复习、首页↔设置。冷启动后首轮和同进程重复切换分开记录。用现有首帧日志关联点按时刻，采集 SwiftUI 长视图更新、主线程调用栈与动画掉帧；有条件比较 11.14.3 与 11.17.2 的同数据测试。测试仅覆盖四个实际可见页签，既有几何用例仍等待已隐藏的「真题」页签，且检测的是位置和尺寸，不能作为流畅性验收。
- **判定**　若主要出现在切入学习库且记录越多越明显，优先改 01。若只在进入复习或回首页时明显，按 02 对应阶段的耗时处理。若空库、连续切轻量页签也卡，再对照公共视图更新与 iPad 渲染轨迹，决定是否收窄根层观察范围或移除探针对各页签的状态传递。先保留系统转场，方向以逐帧记录为准。
- **验收目标**　固定数据下比较点按到首帧、动画掉帧次数和最长停顿，以同一测试方法取得可比较结果。切换仍保留页签导航栈与滚动状态，连续快速点按正确。真机现象和优化前后结果须独立记录。

## 交付记录

- 学习库现在从同一版目录快照取得旧考点名称、类型化考点和错因类型，并在卡片、筛选及题目引用索引中复用；目录数据或索引改变时重新解析。旧逗号标签、类型化同名考点和原有筛选规则继续走现有解析策略。
- 复习题队列按错题记录版本复用 ID 映射；首页/设置其他开销在本轮没有设备轨迹或主线程样本，因此只保留为待测项，没有用源码猜测它们导致了导航卡顿。
- 主导航探针在未挂载或不可见时不创建刷新链接，并在回调检测到失效状态时清理。
- 源码差异核对及 `git diff --check` 已通过。代码编译与工作流强制的领域行为检查待 IPA 工作流执行；该推送工作流不运行模拟器交互测试。本轮没有真机帧率对比，不能报告导航卡顿已由实测消除。
