# 图形推理题持续加载热修

## 现象与源码结论

用户报告图形推理题点击后进入「正在加载」，内容始终未出现。新增错题的普通文字与数字录入同期主观上已恢复顺畅。先用已发布 11.20.2（`4a243a8`）对照当前待发版。用户没有提供是哪条题、从行测错题卡片还是题库进入。两处均使用「正在加载题目…」文案，现有信息无法确认设备落入哪条分支。

- **行测错题卡片。** `LibraryView.destination(for:)` 进入 `LibraryRecordDetailView`。详情按当前记录启动 `.task(id: activePayloadKey)`，后台解码，分页版面通过 `LibraryDetailPageVersion` 更新。已确认，加载显示由「当前记录尚无已提交结果」推导；取消或记录版本在等待时变更会在 `loadActivePayload()` 的守卫处直接退出，该分支不会记录失败或提供重试。布局无法判断是仍在真正解码，还是请求已退出。图推是共用详情路径，图片在题目正文具备后另行加载；当前证据不能把整题转圈归因于图片解码。
- **题库点题。** `QuestionBankCrossPaperReaderView.questionDetailSheet(for:)` 对仅有目录项的题显示加载，并启动一次无身份依赖的任务。`loadCrossPaperWindow` 在页面不可见、目录未就绪或请求不存在时可以提前返回，窗口加载也可被其他锚点请求取消。已确认该弹窗自身没有失败、显式重试或剩余窗口状态变化后的再调度入口，有目录项但未加载正文时会回到加载分支。先按实际复现入口或日志定位，再决定是否改题库分支。
- **普通输入。** 11.20.2 关闭的是行测详情内嵌笔记的正式自动保存，笔记高度修复也只在该场景启用。对照新建错题前后的改动，普通字段未换输入组件，也没有将新建错题草稿快照改成延迟构造。这两处加载缺口和普通输入手感变好目前没有已证实的因果联系。保持现有轻量输入与草稿恢复路径，记录用户反馈供回归对照。

## 目标与实现边界

1. 优先修复行测 → 判断推理 → 图形推理 → 错题卡片。以记录 ID、载荷版本和本次请求标识关联加载状态。当前页仍有效且请求无结果时用可恢复状态收口，记录变化启动新请求并丢弃过期结果，返回／切题允许取消。校验分页可见页从加载切换到正文／错误，无论单条直接打开或多题左右翻页。仍使用后台 JSON 解码与既有轻量邻页预览，避免主线程同步解析整个图题或预读一批题。
2. 用现有 `NativeStatusCard` 样式区分读取失败或请求中断，提供可点的「重试」，重试只请求当前题，返回按钮继续可用。显式失败不得以空内容当成功，编辑、保存和涂鸦沿用已加载有效记录的保护。旧记录大图、图像附件暂缺、老字段兼容按原正文路径处理。图片加载失败局部提示，保留可读题目和选项。若任务等待没有有效完成信号，为可见页提供有限等待后的重试入口，禁止后台循环重试。
3. 如确认题库图推同样触发，针对被点击题补独立终态或重试。即将展示的题由其详情请求负责，目录／可见性变化可重新调度，避免阅读正文的邻题预取覆盖详情的锚点。保留现有窗口大小和资源按需模式，只在该触发路径修补。
4. 需要辅助定位时，仅记录入口、短记录标识、截图对应状态、安全的字节数、版本、请求开始／成功／失败／取消与页面切换。日志不含题干、图片内容或用户输入。

## 验收

- 图推卡片依次打开、返回、重开，再快速进出或多条连续翻页，含一条图片较大的历史题。一条直接打开和多题分页都能看到对应题目内容，延迟结果不会串题。
- 对照一条无图错题、其他行测科目和正常新增错题，连续输入数字、中文并移动光标。保留 11.20.2 手动笔记保存模式。普通输入流畅作为回归要求，性能归因必须有代码或采样证据。
- 在验证条件允许时覆盖取消、当前请求失败、过期结果和重试成功的状态，空数据仍能返回。若修题库分支，验证目录先到正文后到、预取竞争和目录项存在但无正文。
- 不运行云端模拟器。本问题与本轮标签展示补丁同一批次走归档发布。若接收时发布已触发，按当前发布状态收口后再打包，避免重复触发。同一最终发布记录说明可复现的源码缺口、实际修复路径、通过的检查和待真机确认事项。
