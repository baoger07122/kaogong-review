## 目标与修复落点

1. **移除会重入的显示路径。** 针对行测错题笔记，`NativeRichTextDisplay` 在 `makeUIView`、`updateUIView` 只能应用已经准备好的富文本，或者显示现有样式的轻量占位。缺少快照时不得从正文同步转入 HTML/WebKit。覆盖正常阅读、准备失败、已保存版本和恢复／冲突草稿两个预览。按正文标识及版本共用结果，只允许最新可见请求更新对应显示。
2. **保全富文本和原始记录。** 完成保存时优先使用本次编辑文档、会话与版本匹配的已有富文本快照显示，不在保存回调、 SwiftUI 布局、后台切换或恢复弹窗里把刚导出的 HTML 再同步导入。重开与恢复的文本、段落、粗体等使用现有受限解析和原生排版能力；已有图片、表格、公式、引用和列表按既有标记规则处理。无 WebKit 的纯值解析可离开主线程，UIKit 属性装配仍在合适的隔离范围。只读预览降级必须标明，并保持原 HTML 与附件。无法安全导入时不要把降级文本送回编辑器覆盖原始记录；正常短篇和带格式长篇应可继续编辑、保存和重开。保持词语库和申论的其他流程边界。
3. **保持手动提交。** 仅点「完成」提交正式笔记。穷尽检查富文本快照、输入法组合、结束编辑、本地恢复草稿、正式写入、回执及预览各阶段。按会话和版本复用导出，防止同版重复输出。后台和退出只写已有或安全取得的恢复草稿，避免在场景更新的同步回调内做昂贵富文本导入。保存失败显示原因、保留原记录及最后草稿、恢复编辑和重试；成功以正式字段写入与版本回执确认，随后结束「保存中」。诊断日志只记阶段、短 ID、版本、字节数和耗时。
4. **详情可恢复。** 对照图推加载规格验证普通卡片和历史列表，覆盖同题重开、切题、不同题型及分屏场景。当前活动请求应加载正文或结束于现有状态卡及「重试」按钮，返回可用。笔记预览独立于题干和选项加载；任何单条旧记录、附件或草稿异常仅影响该项。保留已有后台读取、翻页与过期请求保护，避免恢复时同步扫描整库或屏蔽错误。
