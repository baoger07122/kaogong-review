## 1. 今日待办隐藏空备注并点按编辑

**现状**　`HomeComponents.swift` 的 `HomeTodoRow` 对每行都渲染占位文字为「添加备注」的 `TextField`，正文还有长按编辑手势。`HomeView.swift` 已有标题点按编辑入口 `beginTodo(_:)`，并根据普通待办、循环实例走不同编辑表单。

**目标与落点**　保留今日待办白色外框、科目圆标、左侧勾选和右侧时间／计时的现有视觉参数。正文扩大为独立可点按区域，至少 44 pt 高，点击标题、已有备注或同一正文区域的空白打开对应编辑表单。标题沿用 `AppTheme.bodyFont`，最多两行；备注以 `AppTheme.inputFont`、次级文字色、行间 3 pt、最多两行显示。备注去除首尾空白后为空时整行省略，标题在正文区居中；列表中移除内联输入框和长按编辑手势。左右按钮独立处理勾选、开始和暂停计时，具有原有的访问性语义。窄窗口优先让标题、备注折行，时间与计时按钮不重叠。

**保存**　普通待办沿用现有「备注」字段。由今日循环实例进入原有规则表单时，增加「今日备注（选填）」，读取和保存当前实例的 `note`，规则表单从每日待办管理进入时省略该字段。扩展 `saveDailyRuleAndReconcileToday` 的同一事务，仅在收到具体实例和备注变更时保存这项内容。校验实例 ID、规则 ID、实例日期和删除状态，跨午夜或实例已删除时给出提示并保留草稿。更新备注时保留当前实例的计时和完成记录。未来实例的备注规则维持现状。

**验收**　对空备注、全空格备注、有两行备注的普通与循环待办检查行高。分别点标题和备注编辑。新增、修改、清空备注后重开确认。点击勾选或计时按钮时只发生对应动作。验证循环实例的备注只属于该日。

## 2. 今日待办使用系统左滑动作

**现状**　`HomeTodoRow` 用自写 `DragGesture`、固定 `-84 pt` 的偏移和弹簧动画揭示按钮。主页本身为纵向 `ScrollView`。循环待办当前以「更多」提供当天和整条规则相关操作。

**实现**　用 `UICollectionView` 的原生 list layout 与 `UICollectionLayoutListConfiguration.trailingSwipeActionsConfigurationProvider` 承载今日待办行，使用 `UIContextualAction` 和 `UISwipeActionsConfiguration`，设置 `performsFirstActionWithFullSwipe = false`。保持现有主页为统一纵向滚动，待办列表按实际内容撑高，复用原行内容与分隔线，避免嵌套纵向滚动、固定行高估算、同一行的自写横滑手势或每秒重载列表。使用待办 ID 路由点击与滑动回调。系统负责滑动、回弹和显示关闭。

**动作**　普通行左滑显示系统红色「删除」，复用 `deleteTodo`。未完成的循环行提供「仅删除今天」和「跳过今天／恢复今天」，按既有确认流程可选择删除规则，只有明确选择删除规则才停止后续生成。已完成的循环行保持现有删除权限。删除某日实例后同日不重新生成。为 VoiceOver 提供与滑动等价的操作。

**验收**　缓慢左滑、快速划满、纵向滚动、连续滑不同的行。滑满只露出按钮，点红色动作后才执行。检查循环待办仅删今天后明天仍可生成，编辑、勾选、计时和便签区纵向滚动均可用。[Apple 的集合视图列表](https://developer.apple.com/videos/play/wwdc2020/10026/) · [系统滑动配置](https://developer.apple.com/documentation/uikit/uiswipeactionsconfiguration)

## 3. 每日待办原位排序

**现状**　`HomeView.dailyRulesManager` 是按创建时间倒序显示的 `ScrollView` 和 `VStack`，`HomeRecordRepository.dailyRules(from:)` 无手动顺序。

**布局和交互**　「新增每日待办」保持左侧，右侧加蓝色「管理次序」，和新增按钮在同一行，文字 14 pt medium、命中区至少 44 × 44 pt。规则少于两条时禁用。点「管理次序」在当前弹窗直接进入排序，右侧文案变成「完成排序」。规则行仍用当前 13 pt 圆角、12 pt 内边距、8 pt 行距，保留标题和说明的现有字号。排序态行右侧用系统 `line.3.horizontal` 提示拖动，暂时停用行编辑、暂停、删除。采用与 `LibraryKnowledgePointTagCollection` 一样的 UIKit 交互移动 API，使用纵向全宽单列。长按规则后跟手移动，其他行即时让位，允许滚动到屏幕外的目标。松手落位立即保存，点「完成排序」退出排序态。取消拖动或保存失败恢复原顺序并提示。

**数据和边界**　在 `daily_todo_rules` 记录持久化规则顺序，初始兼容创建时间倒序，已有排序时新规则仍默认置顶。排序写入单次事务，保留暂停状态、日期及时间，不运行实例生成或重写任务完成记录。今日待办里按同一顺序排列未完成的循环项，只替换这些项在现有列表中的相对位置；普通待办和已完成分区保留当前排序策略。按规则 ID 匹配，孤立历史实例保持原位。编辑规则、暂停、恢复或重启 App 后保留手动顺序。

**验收**　建立四项规则，进入排序，将第四项拖到第二项，松手后关窗重开与重启验证。加入一个普通待办和一个已完成的循环实例验证位置边界。排序前后任务 ID、计划时间、完成时间和计时一致，验证新增规则置顶。[UIKit 原位拖动](https://developer.apple.com/documentation/uikit/uicollectionviewcontroller/installsstandardgestureforinteractivemovement)

## 4. 言语理解考点可修改所属题型

**现状**　`KnowledgePointManagerView.swift` 的文件夹图标连接 `moveTag(_:to:)`，作用域是当前题型的自建分组，`groups.isEmpty` 时禁用。11.13.2 的「归入题型」位于旧考点行的长按菜单，只在当前模块已有题型时出现。已有题型之间的转移没有显式入口。`VerbalLegacyKnowledgePointMigrationPolicy.plan` 将同模块内有题型但只保存考点名称的引用一律判为有歧义，未核查实际是否存在另一个同名考点。`VerbalReasoningKnowledgePointRepository.migrateLegacy` 仍写入目标题型，但遇到任意此类引用就保留旧目录中的标签。管理视图收到提交成功便关闭确认界面，未区分完整移动和部分迁移。仓库检查证明此路径存在，具体标签关联的是哪些实机记录尚未核实。

**布局和操作**　首页 → 考点管理 → 言语理解 → 具体模块 → 考点。旧考点和已有题型下的行，在现有分组、铅笔、删除旁提供显式蓝色「改题型」，12 pt medium，点击区域至少 44 × 44 pt，加入访问性标签「更改题型」及考点名。旧考点页没有分组时省略无可用操作的文件夹图标。点「改题型」打开原生 `Menu`，列出本模块可选的其他第三级题型。当前题型只有自身可选，或旧考点所在模块尚未建题型时，点按后显示对应说明「请先为本模块新建题型」或「当前没有其他题型」。点选目标后复用 `NativeConfirmationDialog`，标题为「更改所属题型」，正文显示考点、原归属和目标，按钮「取消」「移动」。若目标已有同名考点，确认文案明确告知将复用该考点。窄窗口允许考点名折行，保留操作区可点按。

**移动语义与保存**　从 `migrateLegacy` 延伸到明确的 `sourceTypeID` 和 `targetTypeID`，统一处理旧考点归入和同模块现有题型间转移。先生成迁移计划，再以 `(module, typeID, name)` 身份更新相关题目引用、展示字段、轻量索引及两个目录。精确引用直接按身份迁移，题目本身属于其他模块或题型时也能迁移。只存名称的题目结合引用来源、旧目录和题型目录判断，唯一可归属源考点的题目自动跟随；题目已经有题型本身不构成冲突。具备多个可能来源且无足够证据的引用，在写入前通过确认界面的「核对关联」逐题选择归入目标或保留为已明确的其他同名考点，行内显示题目来源或题干摘要。取消核对时保留原数据。完成后同一事务更新引用并从源目录删除标签，提示「已移动至〈题型〉，保留 N 道题的关联」。同时刷新管理列表、录入／编辑选择和筛选索引。关联的题目保留原题型、其他考点、笔记和作答。写入失败不改变目录和引用，保留可重试的确认状态。

**兼容 11.13.2 的部分迁移**　对已经在旧目录和目标目录同时出现的标签，再次选相同目标，即可继续迁移剩余引用并清理旧目录。复用已存在的目标标签及其分组，按完整身份去重，保留其他同名考点的精确关联；若目标标签原本不存在，则追加到目标题型未分组。对无法判断是独立同名项还是前次部分归入所建目标的记录，以用户选定的目标和明确的引用处理剩余记录。没有充分证据时不自动合并其他目标。确认归入前重新校验源、目标与关联记录，失败完整回退。只移除源分组的成员关系，保留分组本身。

**验收**　准备一个旧考点和三道已关联题，包括已设题型却只存旧名称的题。唯一来源时应一步移动，目标目录出现一个标签，旧页立即消失该标签，三个题目关联和本身题型保持正确。再用真实同名冲突验证确认前不创建目标、逐题核对后完整移动、取消不改数据。用 11.13.2 已留下的两边同名状态验证再选同一目标可补齐，目标不重复。再验证已归类考点跨题型移动、目标已有同名、跨模块的精确引用和写入失败。核对重新打开 App 后的目录与关联数量。

## 5. 修复分组后的考点点选和文件夹弹窗

**现状与证据**　`LibrarySelectionDialogs.swift` 和 `LibraryKnowledgePointFilterDialog.swift` 将组选项与未分组选项分给不同的 `LibraryKnowledgePointTagCollection` 实例。两者最终共用 `didSelectItemAt` 和选择回调；组关系未参与选中状态的写入。UIKit 桥接层在宽度尚未明确时可能用 1 pt 测量，且同时依赖独立的 UIKit 布局和 SwiftUI 高度计算。桥接层也没有在接到点按后清除 UIKit 自己的选中态。以上是组内点选和重复点按的可检查路径，尚未确定实机是哪一步中断。`KnowledgePointManagerView` 的文件夹用原生 `Menu`，但它挂在筛选后可能立即消失的行上。选项回调同步写分组，导致同一次菜单关闭期间来源行可能被移除。实机弹窗放大的具体触发还未验证。

**组内点选**　验证轻点是否到达 collection cell、`didSelectItemAt`、表单草稿或筛选状态三处。按可复现场景修正共同组件。用同一个明确的可用宽度驱动 SwiftUI 与 UIKit 的行布局和高度，拒绝用 0 或 1 pt 的临时宽度发布高度。组选项与未分组选项各自保持稳定的视图身份和准确的可点按区域，避免重叠。以具备当前题型归属的考点引用为选中状态来源。UIKit 接收一次点击后释放系统 cell 选中态，由 SwiftUI 选中集合驱动蓝色和勾号，确保再次点击取消。排序和垂直滚动不触发点选。切换分组、题型或进入搜索结果只改变可见列表，保留整个弹窗草稿的当前已选状态；关闭 X 丢弃本次选择改动，确定一次提交。保留原 420 × 468 pt 外框、考点标签样式和分组顺序。

**移动到分组弹窗**　文件夹动作在考点管理页打开单层系统 popover，视觉锚定对应文件夹，呈现宿主使用管理页的稳定视图。打开时保存标签和当前分组的快照，以名称列表展示实际分组和「未分组」，当前分组行右侧用蓝色勾号。标题「移动到分组」为 14 pt semibold，行文字 13 pt、左对齐，最小行高 44 pt，左右 12 pt，标准宽度 240 pt，窄窗口按可用宽度减 32 pt 收缩。列表最多 6 行高度，溢出时内部滚动。短列表按内容收紧，紧凑窗口仍使用 popover 呈现。点击目标关闭弹窗，待系统关闭后按捕获的科目／模块／题型与标签标识保存，当前浏览分组保持选中。重复选当前分组直接关闭。保存失败保留原归属并就地提示。仅更新分组成员记录，考点身份、题目引用和排序不变。[Apple 的 Popover](https://developer.apple.com/documentation/swiftui/view/popover%28ispresented%3Aattachmentanchor%3Aarrowedge%3Acontent%3A%29)

**验收**　在逻辑填空和数量关系各建两个分组，保留一个未分组标签。在新增、编辑错题与学习库筛选分别轻点 A 组选项两次，确认选中、取消，再跨组选两个并确定，检查实际保存或筛选结果。验证空组、长标签、多行、搜索、原位排序和横屏。文件夹弹窗测试当前分组、把最后一行移出当前组、把未分组标签移入组和超过六组，核对始终只呈现一次、大小受限、保存后标签移动且题目关联仍可用。

## 6. 错题编辑转场、保存返回与详情工具栏响应

**现状与证据**　`LibraryRecordDetailView.requestEdit` 对每次请求设置 `pendingEditorRequestID`，详情立即显示「正在打开…」，并用该状态隐藏菜单、禁用涂鸦。正常进入编辑时，`handoffEditRequest` 在主线程用详情已解码对象同步构建完整草稿，`LibraryView.openEditorAfterMenuDismisses` 再异步让出一次执行后推进页面。当前笔记确有编辑或待提交时，路径会先调用 `noteSession.finish`。返回时依赖 `onAppear` 清理请求状态，工具栏可以被该状态延迟。编辑器提交时整体被 `isSaving` 禁用，只有提交成功才退出，保存错误留在原页。11.13.2 未改详情导航实现，但新增 `LibraryView.knowledgePointFilterEntries` 的重复全范围汇总，展示筛选入口时也会读取各记录索引，逐题解码 JSON，并在言语场景重复读目录。编辑保存后查询更新可能放大转场主线程工作。以上能解释等待链路和可能的回归路径，当前无分段实机数据证明各自的耗时占比。

**编辑入口**　详情菜单 → 编辑错题。已载入且笔记无待提交时，菜单一选就进入系统导航转场。优先在当前题对象加载后分段准备轻量编辑初始值，按题目 ID 和内容版本缓存，确认版本一致再复用；其他草稿数据与富文本、附件预览在目的页按需构建。正常路径取消详情页「正在打开」胶囊及占据菜单位置的进度圈。编辑页首屏须及时可见并使用当前题目的真实字段，不出现一帧旧题或空数据可保存的状态。仅笔记有未提交内容且实质等待超过 300 ms 时显示「正在保存笔记…」，短等待不闪出指示器。保留失败提示、原草稿和重试。笔记提交期间不得打开旧版本草稿；草稿字段与保存基线应来自同一记录版本。避免重复点按推入两次，切题或退出时取消旧请求。保留现有题型专用入口。

**保存、返回及回归**　把编辑请求状态和工具栏可见性、启用态分开。导航接收请求后清理详情临时状态，保存成功后按原导航返回，同时恢复「看／刷、涂鸦、菜单」在原定位置。已可见且同一题目的上一份渲染结果可用于转场，持久化后的数据异步刷新；仅依赖当前记录的交互在数据就绪时可用。保持系统返回按钮可实际点按、边缘返回正常，工具栏出现与详情首帧同步，无数秒乱序、闪动、意外开启涂鸦。保留保存成功前的写入保护与失败留页。从 `LibraryView` 的普通视图刷新和导航路径移除候选项的重复构建，目录及引用解析按实际索引版本、范围和数据变化复用，完整候选项按需构建；保留筛选、多选、卡片列表和横滑题序一致。只动有证据支持的详情进入、编辑、保存、返回和考点列表性能路径。

**验收**　分别用纯文字题和含图片、笔记、涂鸦的真题，验证点编辑便进入转场、保存并返回详情后右侧三个按钮立即可见、第一次点返回就响应。覆盖无改动保存、带笔记待保存、实际写入失败、防连点、左右滑题、旧索引、筛选启用与关闭、加载后的首次和连续操作。复用现有 `LibraryPerformanceLog.editorTransition` 与保存日志区分菜单回调、草稿、推入、首帧、提交、返回和工具栏；用于检验修复路径，无需用户先提供实机秒数。
