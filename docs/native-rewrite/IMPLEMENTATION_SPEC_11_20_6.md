## 1. 错题详情首屏和点击性能

**入口和现状。** 从错题列表进入题目详情，以及在详情中左右翻页。`LibraryRecordDetailView.object` 在完整载荷未就绪时从 `indexPayload` 解码；详情多个计算属性会反复读取。首屏索引缺少正确答案、用户选项或题型所需信息时，加载完成会改写选项状态、标题和布局；顶部加载提示也会使内容下移。详情分页以内容版本重建当前页面。

**目标呈现。** 保持当前系统导航栏、返回和工具按钮位置。中间标题继续使用现有 `detailPrincipalTitle` 的 17 pt 半粗主标题和 11 pt 中号次要题型。不得在题目上方临时增删整行加载卡片。加载时只在缺失的题干/选项区域显示 11 pt 次要色提示，并预留稳定高度。冷读首屏不能先显示一套随后改变答案颜色或题目布局的内容；看题模式同一版本的题型、题干、选项、正确状态与选中状态来自一致投影。刷题模式在首次渲染前屏蔽答案、旧选择和复盘字段。保留现有系统动画、重试、超时和取消语义。

**实现落点。** `LibraryRecordDetailView.swift`：按记录 ID 与版本只准备一次索引投影；复用载荷解码协调器及已完成同题缓存；将值类型投影准备放在后台，主线程只提交当前记录有效结果。当前页和相邻页只在展示数据真实变化时更新。针对卡片点击、详情首帧、载荷可用、工具栏出现记录不含题干的阶段耗时；不要全库预解码或同步解析图片。

**边界与验收。** 保留请求代数和版本复核，旧页/旧请求结果不得覆盖当前题。核对中心理解题、图推、纯文本旧题的首次进入、返回重开、左右翻页、窄分屏、慢加载、失败重试及看题/刷题入口。确认同一记录版本索引只有一次有效准备，状态变化不会重复解码；用阶段日志记录首帧与载荷就绪，不能将源码检查当作交互验证。

## 2. 错题笔记安全编辑兼容

**入口和现状。** 错题详情的笔记正文点按进入原位编辑。`LibraryInlineNoteView.prepareNativeNotePreview` 使用纯 Swift 回退解析器准备编辑快照；严格 CSS 元数据检查会拒绝链接、不识别的 class 或样式，导致常见 App 保存笔记被设为只读。

**目标行为。** 对 App 生成及既有常见 HTML，安全保留正文、段落、粗体、下划线、列表、链接和原生图片/表格/公式附件，用户点按「完成」才正式保存。解析失败、损坏、超限和附件标记异常应区分原因；原始内容始终保留，禁止把截断预览写回。进入详情不做整篇同步编辑准备。

**实现落点。** `NativeRichTextFallbackParser.swift` 扩展纯 Swift 编辑解析和格式白名单；`NativeRichTextEditor.swift` 的运行转换完整性检查与其一致；`LibraryInlineNoteView.swift` 将具体拒绝原因映射到可理解提示，并沿用显式完成/取消/恢复和失败保留原文流程。只允许经过验证且能完整往返的声明；有意义但暂不支持的格式不能静默丢失。不得将 WebKit HTML 导入重新放入视图更新、布局或后台切换。

**边界与验收。** 通过 Swift 行为检查覆盖普通短文本、App 风格富文本、链接/列表、原生附件、未知样式、未闭合标记及超限输入。核对可编辑样本往返正文和受支持格式，不支持的样本保持原文只读且给出具体原因。设备内真实旧笔记、保存失败和快速切后台的交互检查留待真机；云端模拟器跳过。

## 3. 复习入口沿用词语详情完整操作

**入口和现状。** 首页 →「词语复习」→「打开原词条」。`WordReviewWordDetailDestination` 传给 `WordLibraryRecordDetailView` 的只有同一 `StoredRecord`，所以详情没有词语库入口已有的编辑、删除、迁移回调。

**目标行为与界面。** 复用原生 `WordLibraryRecordDetailView`：原标题、正文、类别、关联错题和右上角「…」菜单样式不变；菜单提供「编辑词语」「删除词语」，符合条件时提供「迁移旧词语」。窄窗口仍使用同一菜单触达。关联错题继续能查看/编辑/打开原题。

**数据与实现落点。** `WordReviewWordDetailDestination` 调用既有 `LibraryRecordEditorView(kind: .words, ...)` 与 `LibraryRecordRepository` 删除事务/迁移详情路由。编辑、迁移、关联解除均以原 `recordID` 工作；不复制词语详情表单，不增加词条。编辑取消/保存返回同一详情及原复习队列、当前位置和揭示状态；不提交评价。确认删除当前词条后按现有缺失词条反馈和会话过滤继续，不生成空白卡。

**验收。** 从词语库和复习入口对比菜单、正文和关联操作；编辑标题/类型/关联后核对记录 ID 与复习计划/历史；核对编辑取消、可迁移与不可迁移菜单、删除确认/事务失败、关联错题和返回复习会话。源码构建通过不代替设备交互验收。

## 4. 待复习卡片从所选项开始复习当前类别整组

**入口和现状。** 「待复习」类别卡片当前调用单项 `beginDueSession([wordRecordID])`，而底部「开始复习」传入当前类别全部到期词，因此卡片显示 `1 / 1` 后即结束。

**目标行为。** 点某张卡建立同一类别当前完整待复习队列，保留现有排序并将所点词条旋转到首位：所选项之后的顺序不变，所选项之前的项排到队尾，每个有效 ID 一次。底部「开始复习」从该类别第一项开始。现有卡片、评价按钮、揭示样式不变；右上进度使用实际队列长度，提交成功后自动推进，最后一项后才回列表。

**实现落点。** `WordReviewView.beginDueSession` 统一从 `categoryDueWordIDs` 生成队列，可选起始 ID；从当前快照过滤暂停、已删除、无计划及重复 ID，沿用 `.initial`/`.due` attempt 类型和现有 `submissionID` 去重机制。保持选择类别和既有会话内存状态，不把队列跨类别合并。

**边界与验收。** 三项以上时点中间项，验证 `1 / N`、后续原序、此前项目位于队尾及完成后返回。另核对底部首项、只有一项、类别切换、过期/删除项、快速重复点击、保存失败重试，以及打开原词条编辑后返回仍在相同队列位置；失败不得推进或重复评价。

## 5. 首页关联错题使用根层涂鸦会话

**入口和现状。** 从复习入口的词条详情打开关联错题，点右上角「涂鸦」。`HomeErrorDetailDestination` 创建局部 `LibraryDoodleSession`，详情进入涂鸦后隐藏按钮；`RootTabView.LibraryDoodleRootOverlay` 观察的却是词语库根会话，故首页路由缺少工具栏。

**目标行为。** 首页与词语库详情共用 `RootTabView` 的 `LibraryDoodleSession` 和根层 `LibraryDoodleRootOverlay`。点「涂鸦」后沿用现有工具栏、画布、笔/橡皮、退出和保存提示；关闭后恢复按钮及阅读。不得再挂第二套工具栏/画布。资料分析双栏、普通题、分屏及既有保存边界沿用现有逻辑。

**实现落点。** `RootTabView` 将同一会话注入首页 `NavigationStack`；`HomeErrorDetailDestination` 改为读取环境会话并在其详情复用。为路由退出和 tab 切换清理属于当前题的活跃会话；保留原记录 ID、当前题版本和保存回调，切题前完成/取消策略沿用共享会话实现。

**边界与验收。** 从词语复习原词条打开关联错题，确认画笔工具可见、能写一笔、退出后重开仍显示已保存笔迹。对照词语库和行测详情；检查回退原词条、切题/切 tab、iPad 分屏、资料分析双栏、保存失败和无遗留遮罩。实际触控验收标注为未执行，除非使用设备完成验证。

## 6. 错题详情与编辑页使用各自的错因文案

**入口和现状。** 行测错题详情的资料分析和数量关系有专用错因展示行，两处目前显示「错因说明：」。编辑错题表单使用「错因说明」，与「错因标签」区分。详情点属性打开的快捷编辑弹窗标题是「错因说明」，输入框标签是「错因」。

**目标与实现。** 将 `LibraryRecordDetailView.swift` 的 `dataAnalysisCauseMetadata` 和 `quantityErrorCauseMetadata` 展示标签改成「错因：」。完整编辑表单继续显示「错因说明」。快捷编辑弹窗同样属于编辑态，标题和输入框标签统一用「错因说明」。沿用原有尺寸、字体、颜色、间距和对齐，窄窗口保持现有换行行为。

**边界与验收。** 保留空值提示、原有分科专用文案、标签、卡片布局和存储字段。分别打开有错因的资料分析、数量关系和已经显示「错因」的普通错题，对照详情、快捷编辑（如支持）和完整编辑。用现有文本保存并返回，核对只切换显示文案，正文和标签可正常读取。

## 7. 查看释义直达原词条，历史按类别筛选

**入口和现状。** 「词语复习」里的「查看释义／查看辨析」先在复习页绘制一份正文，再由「打开原词条」进入词语详情。历史列表按时间混排各类别。

**目标呈现。** 回忆卡片保留现有标题、进度和蓝色按钮。点击后直接进入原词条详情，沿用原正文、关联错题和右上角操作。详情底部用现有 14 pt 半粗、46 pt 高的「不会／模糊／掌握」按钮，窄分屏等宽排列，长正文可滚动到最后。评价成功后自动回到下一词的回忆卡，最后一项回「待复习」；返回可重新回忆当前词。

**实现与数据。** 复用 `WordReviewWordDetailDestination` 和 `WordLibraryRecordDetailView`，以本次会话项驱动导航和评价。移除重复的释义正文和二次入口。复习期间编辑或查看关联错题保持队列和当前位置。保存失败保留详情及当前词，可重试；已删除或不可用的待复习词条跳过，不生成评价。

**类别与排序。** 「历史」复用「待复习」的横向胶囊选择器样式，默认「全部」，其后为成语释义、成语组辨析、实词释义、实词组辨析。按评价时保存的类别筛选，旧类别原样保留在「全部」，类别内历史按最新时间在前。两个页面的筛选独立，窄分屏横向滚动。用户本条消息未给出新的待复习排序，沿用现有到期日、标题、ID 排序及第 4 项的队列规则。

**验收。** 分别从释义和辨析入口一步到原词条；确认底部评价、返回当前词、成功自动进下一词、末项退出、失败重试和删除后继续。历史依次切换四种类别与「全部」，核对分类、时间排序、空态及窄分屏下可横向滑动。

**本地交接检查。** 第 3、4、7 项已在 `WordReviewView.swift` 实现并通过 Swift 语法解析和补丁空白检查。iOS 类型检查、设备目标归档和实际点按交互尚未执行。
