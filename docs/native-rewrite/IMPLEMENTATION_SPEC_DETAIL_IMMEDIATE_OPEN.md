# 错题卡片立即打开

## 现象与原因

行测错题卡片点按后，11.21.1 的代码先改待打开状态，再经过 SwiftUI 任务等当前题解码或最多 180 毫秒才推入详情。录屏能看到先停留在列表，随后进入已有内容的详情，手持录屏无法精确确定触碰时刻和耗时。

## 实现

- 点卡片当次立即推入导航，去掉点击后的任务等待和 180 毫秒期限，保留标准系统推入动画和卡片按压样式。不在点击回调解码 JSON 或主动读图。
- 在行测已出现的卡片上延后少量时间准备体积不超过 512 KiB 的详情，最多 2 次并发解码和 6 条完成快照。后台沿用原解码队列。滚离或退出列表的任务随卡片取消；导入清空快照。命中时用完整记录进入，按记录和版本校验数据。
- 没有完整快照时，用列表已准备的同一记录题干作首屏内容，复用详情题干的字号、行距、边框、上下间距和对齐。完整数据随后在当前页面显示。未就绪时不显示选项、答案、旧选择或复盘属性；刷题模式继续屏蔽旧答案。无题干的图推和外链题保留延迟行内提示、失败重试和返回，允许读取耗时，没有单独的加载路由。
- 保留卡片列表和详情的筛选顺序、现有上下题、笔记及涂鸦归属。连续开题、快速返回、恢复备份和编辑过的记录不得误用上一版本快照。宽窄布局沿用详情内容区边距。

## 验收

- 点已经出现的文本错题和刚滚到的文本错题，核对点按后直接启动导航，首屏能读到题干。返回再开同题和开另一题，核对正确记录及选项。
- 验证刷题模式首屏无答案、图推大图、读不到记录时可以重试或返回，以及窄分屏和左右切题。比较录屏里的「点按 → 导航开始」和「导航开始 → 内容出现」两个时间段。
- 保留在本地批次，收到「发布执行」再交 Luna。

## 本地交付

- 已核对点击路径为同步导航、后台预读受限、复用按记录版本及原数据校验。新增代码片段通过 Swift 语法扫描和 Git 补丁检查。
- Windows 工作区未执行 Xcode 类型检查或 iPad 计时验收。缓存未命中时，完整题目出现时间仍受实际读取和渲染影响。
