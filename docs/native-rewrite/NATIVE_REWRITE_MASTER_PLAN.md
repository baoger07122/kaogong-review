# kaogong-review 原生 iOS 完整重写计划与阶段验收表

> 本文是原生重写的总计划、交付清单和用户验收记录。功能基线为 Web `v8.25.3`，原生开发分支为 `codex/ios-native-rewrite`。

## 1. 验收规则

每个功能必须经过三个层级，不能只凭“页面已经写出来”判定完成：

| 标记 | 负责人 | 含义 |
| --- | --- | --- |
| 开发 `[ ]` | Codex | 功能代码已经实现，并完成代码层自查 |
| 构建 `[ ]` | Codex / CI | 自动测试、编译、IPA 结构或数据检查已经通过 |
| 用户 `[ ]` | 用户 | 已在 iPad 真机操作并确认功能、交互和数据结果符合要求 |

阶段完成必须同时满足：

- [ ] 本阶段所有必做项的“开发”和“构建”均已勾选。
- [ ] 已生成对应版本的未签名 IPA，并保存到 `downloads/native/版本号/`。
- [ ] 已提供本阶段变更说明、已知风险和测试步骤。
- [ ] 用户已逐项检查，关键项的“用户”栏均已勾选。
- [ ] 用户明确回复本阶段通过，才能进入下一阶段的正式签收。

状态约定：`未开始`、`开发中`、`待真机验收`、`有问题`、`已通过`。用户验收发现问题时，不删除原条目，在“问题记录”中登记并重新生成 IPA。
