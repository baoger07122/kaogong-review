# 错题笔记保存与题型管理科目跳转

## 1. 短文字和表格错题笔记的统一保存

- 入口为错题详情 → 错题笔记 → 粘贴文字或富文本 →「完成」。两份截图分别显示短文字和含表格正文保留在恢复草稿区。源码中，恢复草稿的写入与版本再读取分属两个异步调用；退到后台的草稿写入可推进相同内容的版本，从而被当成保存冲突。旧草稿只有整题版本，恢复时题目元数据变化也可能被识别为笔记冲突。截图无法确认当次失败分支。
- 本地草稿由现有存储 actor 原子写入并回传实际存储版本。同题、本次请求的内容及原笔记基准一致时可采用较新回执；内容、题目或基准变了则保留较新草稿并停止本次写入。明确的正式保存和正在结束输入时，不由后台回调重复启动恢复写入。仍在页面退出回调保存尚未托管的当前编辑。退出后结束已卸载的编辑会话，返回同一详情时先保留内存草稿，再核对磁盘恢复记录。显式保存队列使用已落盘的恢复草稿，在正式写入前再次核对，避免用队列编号改写恢复草稿。
- 新恢复草稿加可选的原笔记内容指纹，兼容旧 JSON。恢复或直接保存时，核对存储题 ID 和当前原笔记；仅有非笔记字段变化时，在最新整题载荷上提交。正文确实变化或旧草稿无法证明基准时继续使用已有的「以恢复草稿为准」流程。正式保存仍核对写入回执及题目实际笔记字段，成功后按版本清理相同内容的恢复草稿。
- 保留标题下的具体失败提示及未保存区的「保存草稿」。HTML、表格和图片使用统一保存机制及现有序列化，确认成功前保留草稿。无新周期自动保存。
- 验收：在两道无笔记的错题分别粘贴短中文和带表格的内容，点完成后核对「已保存」，返回重开检查全文及附件。检查保存过程中切后台、较新的同内容与不同内容草稿、重启恢复后修改题目标签、原笔记真实并发修改及旧草稿的恢复入口。

## 2. 设置里的题型管理可选择科目

- 入口为「设置」→「题型管理」→ 任一行测科目。现有科目行使用直接挂视图的链接，而设置页的导航栈维护 `SettingsRoute` 路径。将科目也注册为同一类型化路径的一段，由设置导航栈统一下发目的地。
- 科目行使用原生列表导航，沿用五科图标颜色、14 pt 常规字重、至少 44 pt 高和整行命中区。数量关系进入其独立的题型列表，其余科目进入现有模块列表。模块页与题型排序组件保持原入口。长名称和窄分屏使用原生列表收窄方式。
- 验收：在 iPad 设置页依次选择数量关系、言语理解、判断推理、资料分析、常识判断，确认打开各科目录。返回上级后可继续选择科目，从模块进入现有新增、编辑、拖动排序页。
