# Luna 同批执行规格 · 申论工作区、考点选择、题型展示、速算与富文本

申论界面方案已确认。同批涵盖考点选择、题型详情、速算首进与同组重复出题，以及错题笔记图片保存和富文本粘贴。本次交付为执行规格和原型归档。

## 0. 执行口径和原型

- 本文件是这一批的执行和验收依据。申论以右上涂鸦、同页双栏和按题生成答题纸的最后一版为准；旧规格里 900 pt 以下切页、材料栏内加材料、右栏重复题干和作答状态的做法不再适用。往期其他缺陷不自动纳入。
- `SL-01…SL-06` 对应申论工作区，`KP-01…KP-03` 对应考点选择器，`DT-01` 对应行测错题详情的题型展示，`SP-01…SP-02` 对应速算首进与同组出题，`NOTE-01…NOTE-02` 对应图片保存和富文本粘贴。各项在各自入口实施并按本批验收表核对。
- 参考 [原型及图纸索引](prototypes/shenlun-reader-answer-sheet/README.md)。示例卷名、示例答案、现成笔迹、计分结果和浏览器专用路径仅用于验收和演示，不内置为用户资料；正式 App 用系统图标和现有主题。图纸决定布局和信息量，本文件决定真实保存、数据归属、无障碍和边界，HTML 模拟动作不是现成 iOS 功能。
- **当前基线（源码核实）**：`native-ios/project.yml` 的 iOS 最低版本是 17.0，iPad 原生。`RootTabView` 现有「首页／学习库／复习／设置」，申论仍通过旧的 `ShenlunRecordDetailView`、`ShenlunAdaptationView` 打开；未找到已接好的新版申论工作区或专用分析接口。不能假设浏览器原型已在 App 中，也不要用 WebView 套原型作为实现。
- 不批量删除或就地改写旧申论、旧错题、历史作答或笔迹；仍可通过原申论详情／兼容入口验证原文。是否清理历史数据另按明确授权处理。除这批必要入口外，保留行测、已有复习、设置及速算的样式和行为。

## SL-01 · 入口、列表和题目录入

**入口。** 底栏默认「首页、行测、申论、设置」，保留 `RootTab.library` 的既有 ID 与页面路径，显示名改「行测」。单独的申论根页用独立导航栈。设置首页增加「页面模块 → 显示复习」系统开关，首次默认关闭并持久化；开启时「复习」插在「申论」和「设置」之间，设置始终最右，点击开关留在设置页。只改变复习入口的可见性，不清空复习数据。行测常规分类不再将申论当作科目展示；旧申论由申论入口的兼容路径可查阅。

**列表。** 顶部「单题练习／套卷练习」，首次默认单题，详情返回恢复之前的入口与筛选。单题筛选依次「全部／单一题／公文题／作文题」。单题卡使用题干摘要、来源、原题号、题型和实际进度；套卷每套一条，显示题数、已完成独立作答数、已确认评分数，依赖实际题目而非样例总数。类型字段继续用于录入与筛选，不出现在工作区卷名下面。

| 进表单的方式 | 表单标题 | 保存及返回 |
| --- | --- | --- |
| 单题列表「新建单题」 | 录入单题 | 保存题目 → 新题详情 |
| 套卷列表「新建套卷」 | 新建套卷 | 保存套卷 → 首题详情；允许后续继续加题 |
| 套卷详情全窗「··· → 添加题目」 | 录入套卷题目 | 保存题目 → 新题；不覆盖卷中旧题 |
| 任一详情全窗「··· → 编辑题目」 | 编辑题目 | 保存题目 → 返回原题与编辑前的阅读位置；取消不改任何已保存内容 |

同一表单左「取消」、中标题、右「保存题目／保存套卷」。≥900 pt 表单双栏，左「题干与作答要求」「预录参考答案」，右「题目信息」「给定材料」；<900 pt 按「题目信息、题干与作答要求、给定材料、参考答案」纵排。表单宽度阈值不套用工作区的 680 pt。卡片圆角 16 pt，内边距约 20 pt、组间 14–16 pt。字段标题 13 pt medium、输入文字 15 pt、主体输入区最小高度题干 160 pt／要求 90 pt；键盘不遮住当前字段。新建套卷必填名称，每题必填题干、带默认「单一题」，可填写来源、原卷题号、要求、满分、字数上限和字数下限。字数为正整数；填下限时必须同时填上限且下限 ≤ 上限。清除上限可恢复不限字数；需要同时清掉已填下限。保存失败停留当前编辑页，保留所填数据和暂存附件。

**材料写入边界。** 仅表单能「粘贴文字」「导入 PDF」「添加图片」；套卷内另外能「关联本卷材料」。预览顺序及页数；PDF 从用户选择的明确页范围导入原页，图片按原顺序显示，未确认前不自动把整卷或参考答案并入左栏。套卷关联按材料 ID 多选；可明确设「无需材料」，与尚未设置不同。新增暂存材料默认归当前题，点击主表单保存才一并落盘；取消或失败不得留下可浏览的孤立材料或改变旧稿。不得为保存附件重生成题 ID。预录参考答案与作答分别存，完成当前题独立作答之前不能在材料、表单详情或工作区入口看到已封存答案；编辑已存在题时仅提示参考状态，从复盘修改参考正文。

实现落点：`RootTabView`、`SettingsView` 接根入口；新工作区按练习与题目 ID 路由，参考仓库已有导航写法。可复用 `ShenlunAdaptiveTextEditor` 的 UIKit 文本输入；旧适配页的旧字段保留兼容，不把旧阅读卡截取当成新版双栏。

## SL-02 · 同页双栏、顶栏与切题

对照 [01 双栏](prototypes/shenlun-reader-answer-sheet/01-dual-pane.png)、[05 编辑入口](prototypes/shenlun-reader-answer-sheet/05-edit-location.png)、[06 竖屏](prototypes/shenlun-reader-answer-sheet/06-portrait-dual-pane.png)。布局按窗口内容宽度计算，不按设备名、横竖方向或 size class 强制定型。

| 区域 | 规范 |
| --- | --- |
| 全窗顶栏 | 左返回；中部最多一行卷名／练习名，系统 16–18 pt semibold；右侧顺序「···、图层图标、涂鸦胶囊」。空间不足先让标题截断，并保留其完整辅助名称。去掉「作答中」状态胶囊、卷名下「套卷／第一题／单一题」和右侧重复题号卡 |
| 主体 | 有效宽度 ≥680 pt：左约 55%，右约 45%、最少 280 pt，中间一条约 1 pt 分隔线；分别滚动，顶栏固定。<680 pt：同路由纵排材料和答题区，允许滚动到两区；没有「材料／作答」切页的分段选择器。极窄顶栏可两行，图层与画笔仍在同一行靠右 |
| 左列 | 上方仅可横滑的「材料 1、材料 2、…、作答要求」索引，约 50 pt，选中蓝字加下划线；下方纸面；底部缩放及独立纸页计数（例「1/10 页」，页数由实际纸页算出）。无「给定资料」额外标题、无材料新增按钮 |
| 右列 | 页头「答题纸」15–16 pt semibold；右侧一处 `‹ 1/5 ›` 题序胶囊（字体 14 pt semibold、等宽数字、实际触控至少 44 pt）。左右箭头切前后题，首尾对应方向禁用；点数字展开短题序列表。单题／只有一题时隐藏该控件。下方答题纸，已有疑惑默认折叠；底部「记疑惑」左于「完成作答」，保持可达。独立作答期间无右列重复题干或状态卡 |
| 视觉 | 页面白底与浅灰纸面背景；纸页白底，右栏为浅灰衬底和独立白纸。交互蓝用 `AppTheme.accent`，次级色用系统 secondary。标题由设备字体缩放，纸页只改缩放比。键盘只让右栏编辑器／底部按钮避让；不把左栏重置到第一页 |

**状态规则。** 题序表示当前题在实际题目数组的顺序，不能用原题号代替 ID。纸页编号表示当前纸页，左边翻纸绝不切换右边正在写哪道题。切题前提交旧题的当前草稿和阅读锚点；若当时打开的是「作答要求」，在题目区定位目标题的锚点。否则先找目标题上次阅读位置、其次其首份关联材料、最后首份可读材料；无材料直接展示「作答要求」。两个面板的滚动位置分别管理。切题不丢左栏缩放或另题草稿。返回列表、取消编辑或窗口尺寸变化时，恢复可验证的原锚点；锚点不存在用同材料最接近的页、再退回材料开头。

实现落点：一个 SwiftUI 详情容器，使用显式双栏宽度和细分隔线；各列自己拥有滚动、焦点与局部状态。不要用默认会在紧凑宽度折叠成跳页的导航结构承担两个工作区域。各顶栏控件仅有一个实例，优先安排兼容 iOS 17 的安全区布局；如使用 iOS 26 API，必须有条件分支且不叠两条顶栏。

## SL-03 · 材料纸面、卷尾题目页与原件

对照 [03 作答要求](prototypes/shenlun-reader-answer-sheet/03-question-paper.png)。生成文本纸页采用固定逻辑纸宽 612 pt × 高约 866 pt；留白起始参考上 68、下 57、左右各约 70 pt，中文仿宋 11.31 pt、英数 Times New Roman 近似尺寸、基线 20.6 pt、正文自然段首行约 22.63 pt 缩进，段距为 0，正文两端对齐、末行左收。字体缺失用合法可用仿宋类字库并记录，搭配纸面样张检查换行，不把换一款同字号字体当成一致。材料开头只显示小字「材料 1」（12 pt semibold、深蓝、下留约 11 pt），续页从正文开始。App 不生成重复卷名、页头「给定资料」、纸面页脚或页码；导入原件保存原样，原件自己包含的版式不做破坏性裁切。

- 照真题卷尾的形式，最后材料结束后「作答要求」**整组另起纸页**。首张标题「作答要求」（17 pt semibold，左对齐），各题原题号（约 12 pt 加粗）居中、题干加粗、要求常规字重，排版保留原顺序、分值和自然换行；原文已带分值或「要求：」时不重复补入。放得下的五题可同页，放不下才续页。不同类型的纸页不混排，长题跨页保留尾段，题号至少与题干首行同页。
- 题目页生成自同一练习的有序题目数据，编辑保存后立即重排，带稳定的题目锚点。不是可选 PDF 附件或某个材料；不能把它写入材料关联与提交给 AI 的材料范围，不能显示参考答案。此版题目页为阅读，材料图层及笔按钮在该页禁用，不把旧活动层借给题目页；切回材料原笔迹仍在。
- 粘贴文本保留原段落、标点及数字，不能把普通行折行当作新段。导入 PDF／图片按已选原页入当前材料组，读取图像与 PDF 页面保留完整源内容、方向和次序；如同一源文件的同页被明确选入不同材料，两者有各自材料页 ID、批注不会串。切换窗口只改变视觉缩放，不重分页；更换原文有坐标变化时建立新版本而不是覆盖旧纸页上的笔迹。

## SL-04 · 通用涂鸦位置、透明画布和图层

对照 [02 图层](prototypes/shenlun-reader-answer-sheet/02-layer-popover.png)。以现有 `LibraryDoodleOverlay` 的全窗右上为锚，用原组件的顶部 `max(safeArea.top + 5, 28)`、右侧 `safeArea.trailing + 12` 的定位语义，不重复加 safe area。保留 `NativeDoodleToolbarCapsule` 40 pt 高度、磨砂胶囊、原图标顺序及笔具设置；紧邻胶囊左侧是叠片按钮，不另放材料栏。材料页默认展开，点胶囊「×」收起后在原位显示涂鸦入口；保留已显示笔迹，图层按钮仍可用。复用 `PencilDrawingController`、`NativePencilDrawingSettingsPanel` 的笔色、粗细、橡皮大小和手指开关；测试 Apple Pencil 与手指滚动。保留其他功能的涂鸦位置；不把 `LibraryDoodleInteractionShield` 或旧全窗变暗遮罩带到申论。

| 操作 | 实现与保存边界 |
| --- | --- |
| 打开图层 | 叠片按钮下方锚点浮层，245–270 pt 宽、14 pt 圆角、单行 44–48 pt。浮层层级高于两栏索引，水平限于窗口。首行直接图层列表，无「图层 / 材料 1 / 关闭」标题行 |
| 行内容 | 左到右：该页笔迹缩略图（约 34×31 pt）、名称、眼睛、更多。活动层一处浅蓝底，无「可见／已隐藏／当前图层」副标题。眼睛正常／划线反映单层状态，VoiceOver 有层名和状态。点击同叠片、外部或 Escape 关闭；不关闭画笔 |
| 新建／改名 | 无层的新材料默认「批注」。底部「＋ 新建图层」输入有效名称，保存后放最上层并激活；行内「··· → 重命名」改当前层名称，保持稳定 ID、顺序和所有笔迹；校验空白，取消不写。原型示例的「通读批注」「对照补记」不是正式预置 |
| 选择／显示 | 点层名激活；若该层隐藏，顺带显示它。隐藏活动层选最上方可见层；所有层隐藏时停笔，恢复时从可见层重新选。浮层底部眼睛是本次阅读的整体显隐，恢复沿用各层原设置，不批量改写单层可见位 |
| 书写作用域 | `practiceID + materialID` 共享图层名称、顺序、可见性；`practiceID + materialID + materialVersionID + pageID + layerID` 单独存一份页笔迹。套卷多题共用材料时看到同一材料的批注，题目作答及疑惑互相独立。橡皮、撤销、清空仅活动页活动层，不改其他层 |

同材料翻页沿用层名与显隐，缩略图更新为当前页；切到另一材料刷新范围并取消未提交的改名输入。笔迹层与纸页使用同一原点、逻辑尺寸、滚动和缩放；默认 Apple Pencil 写，手指滚动/缩放，开手指涂鸦才允许手指写。仅活动页的活动层是透明可编辑画布；其余层只提供轻量预览。提交最近笔迹后再切页、切层、收起或离开，异步回调按原页、原层和版本定址。失败保留可重试缓冲并明确提示，不能把写失败反馈给新页或丢掉最近一划。若旧图可确认页坐标，映射至默认层；无法确认坐标的旧整页笔迹保持原版可读，禁止猜坐标批量迁移。图层删除、拖动重排和 AI 识别笔迹均不借此新增。

## SL-05 · 右栏答题纸、字格算法与键入

对照 [01 答题纸](prototypes/shenlun-reader-answer-sheet/01-dual-pane.png) 和 [04 作文字数边界](prototypes/shenlun-reader-answer-sheet/04-essay-sheet.png)。格纸位于右栏，白底约 12 pt 圆角，内容内边距 10–14 pt。顶部「键入」在左、等宽 `76/250 格` 计数在右。每行 25 个正方格，行间留约 0.4 格高，线用浅红（原型约 `#B57F82`，终止刻度适当加强），数字刻度在相应格下方不盖正文。每张最多 24 行／600 格，张间有轻分界；多张才显示 `1/2 张`，总容量仍是原题上限。每 100 格标一次，另标字数范围下限和最终上限；下限不增加格数。列宽变动只缩放格子，不改变一行 25 格。

| 数据输入 | 必须输出 |
| --- | --- |
| 上限 250、300、450 | 分别 10、12、18 行，一张纸 |
| 下限 1000、上限 1200 | 两张各 600 格，第 2 张标出 1000 与 1200 |
| 上限 257 | 前十行共 250 格，末行左对齐七格，后 18 个位置不画格线 |
| 未设上限 | 不造假格纸；显示「未设字数上限」，仍可用连续编辑器 |

**唯一原文与计格。** 保存一份连续文本 `answerText`，格纸只是它的投影。汉字、标点、数字、英文字母按用户感知的字符（Swift `Character`）逐一入格；显式空格占格不画字。换行在计格时将未满行的剩余格留空；恰好满行后回车不额外跳空行，显式空白段落另起一行，正文末尾换行不虚增已占数。计数等于最后一个实际输入字符所到的格号（含其之前的空格、跳过的行尾）。只渲染上限以内格，超限提示「超出 X 格，原文未截断。」；撤销或改短即更新。禁止按格存字段、用上限截断粘贴或改掉输入的原文。作答纸边界是练习规范，不表示官方计字规则。示例：`甲，乙。` 换行再打 `两个字符`，首行占 1–4、后四字占 26–29，显示 29 格。

点格纸或「键入」在右栏就地显示一个原生连续编辑器，实时刷新格纸；还可「收起」和继续编辑，保留复制、粘贴、光标、撤销和中文候选。中文输入法的标记文本不写入正式草稿或截断，候选确认后再把完整字符映射。空白答案不能完成；超上限仅提示，用户修改或进入复盘时不能丢被提示的部分。切题、保存、恢复都用题 ID；编辑上限只重绘格纸，不覆盖作答。无材料也能作答。此版不新增在格中逐字手写、OCR 或 PDF／Word 导出。

## SL-06 · 作答、复盘及数据保护

右栏点「记疑惑」可以记录多条，绑定当前题、可选正读的材料／题目页锚点；已有疑惑可展开、复盘时保留原文。点「完成作答」先保存原文，再进入右栏「对照答案／逐条答疑／评分与分析」，左栏继续可读；按题封存和解锁参考答案，作答与参考分别编辑保存。已完成答疑或明确标为待验证后可评分，无疑惑可直接评分。确认结果才写入；改动已评分题的题干、要求、作答、参考、字数规则或材料集合后保留旧评分并标「需复核」。

## SP-02 · 速算新开一组和重来时避免同题

**入口与源码原因。** 首页 → 速算练习 →「开始练习／开始自定义练习」，以及结算页「重来」。反馈中「三位数乘一位数」同一组的第 8、10 题都是 `568 × 8`。11.17.2 和发布分支 11.17.3 的 `SpeedQuestionEngine.questions` 都按题量逐次调用 `make`。三位数与一位乘数每次独立从 100–999、2–9 抽取，同一组合再次抽中也会追加，且每次都有独立 UUID。将 `(568, 8)` 连续代入该分支，会得到两个 ID 各异、题面和答案都相同的对象。自定义还有第二条可复现路径，`568 × 2` 和 `568 × 9` 在 `applyCustomNumber` 将乘数换成固定的 8 后也会成为同一题。`SpeedPracticeView.start` 直接使用出题结果，`SpeedResultView` 按 ID 逐行显示原有答题记录，因此重复在组题时已经产生。

**执行指令**

1. 在 `SpeedQuestionEngine.questions` 为每组新题创建一次已用题面集合。候选先经过 `make` 和 `applyCustomNumber`，用最终 `expression` 作为去重键，再加入题目数组。估算题的现有 `expression` 包含原数、估算值和待修正的初始值，三项相同才是同题。普通算式以最终运算符和有序操作数为准，整个组共用同一个集合。同答不同题均可入组，例如 `190 × 4` 与 `380 × 2`。同一算式来自不同题型时仍只入组一次。`id` 继续用于标识作答与结算记录。
2. 遇到重复时为该位置补抽，循环出题按既有题型顺序补满该位置，随机出题从已选且仍能提供新题的题型抽取。每个位置最多重抽 8 次，之后从该题型可用的参数组合惰性找第一道未用题。复用随机出题的有效范围、定制数字替换和计算公式。查找找到一道即停，避免预先展开大题池。估算练习按本组估算表准备可用原数及对应范围，复用 `SpeedEstimateRules` 的 1.5% 门槛。生成时最多准备一次，重抽和补题复用同一批有效范围。
3. `SpeedPracticeView.start` 只有收齐设置的题量才进入新一轮。合法题量仍按 10／15／20 题出完整一组。按当前条件无法补满时留在发起页，使用系统提醒「题目不足」和「当前设置无法生成所选数量的不同题目，请调整题量或练习设置。」估算表没有符合门槛的候选时提示调整估算表。提醒提供「好」关闭，保留设置及原结算结果。仍按现行规则计算答案、计时和判分，生成阶段完成去重后再开启练习计时。
4. 「重来」走 `start` 生成另一组，已用集合按组初始化。「复练」继续走 `SpeedPracticeFlow.retryQuestions`，按原顺序取本轮答错的题，保留题面与正确答案并重置作答和用时。历史结算按已保存的实际题目和答题结果读取。

## NOTE-01 · 错题笔记插图后完成、回看和重开

入口为行测错题详情 → 错题笔记 → 底部工具栏「＋ → 图片」→ 相册 →「完成」。覆盖空笔记只插一张图、正文前中后插图及多图。源码核对了本工作区 11.17.2（build 151）和发布分支本地引用 `deb302b` 的 11.17.3（build 152）。

**源码确认的失效路径**

1. `NativeRichTextEditor.swift` 的 `insertImage` 将图片作为 `NativeImageAttachment` 插入 `textStorage`，成功分支随即调用 `publishNow`。这发生在 `updateUIView` 处理命令期间，且 `publish` 在写外层 `$draft` 前先更新 `lastHTML`。只要外层绑定在收起键盘时仍为会话初始空值，`updateUIView` 就会通过 `lastHTML != html && !view.isFirstResponder` 进入替换分支，载入 `preparedInitialAttributedText`，再由 `setPublishedHTML` 给旧内容递增版本。当前判断条件允许这一写回发生在同一会话结束编辑期间。
2. `LibraryInlineNoteFinishPolicy.finalRevision` 对同一题、同一会话的较大版本直接放行，且 `saveIsConfirmed` 仅比较所选 HTML、回执和实际字段。按现有分支代入「结束前版本 7 有图，结束输入时返回的仍是有图内容，之后读到版本 8 的空快照」，最终会选版本 8，空字段也能通过一致性校验。这里缺少来源校验，用户插入的附件可以被旧草稿覆盖。该反例在 11.17.2 和 11.17.3 共有。
3. 11.17.3 另有可独立触发的保存冲突。`LibraryInlineNoteView.onAppear` 将只读用的 `更新时间:payload字节数` 登记进保存状态，`beginEditing` 则取得写入用的 `更新时间:SHA256`。图片插完快速点「完成」、该草稿还未由 `onChange(of: draft)` 注册时，`commitFinishRevision` 可把写入基线换回只读键。即使记录字节完全相同，两键也不同，`writeNote` 的版本校验会判冲突。这个分支会产生保存失败，须与已关闭编辑后显示空白分别验收。

以上为可按源码构造的失效条件。用户设备上的分支仍以对应版本的实机测试确认。页面出现「点击添加错题笔记」代表预览读值为空，记录的 `note` 是否也为空由落盘核对决定。

**执行指令**

1. 在 `RichTextTextView.Coordinator` 以内存中的 `textStorage` 作为活动编辑会话的正文来源。初始化只在绑定到当前题和新会话时装入准备好的内容。相册、键盘失焦、工具弹窗及完成提交期间的 SwiftUI 更新只接收绑定回执，旧的 `preparedInitialHTML` 或 `$draft` 不得回灌当前会话。保留独立的编辑修订号，只有用户编辑及输入法提交等真实内容变更才推进它。真正切题或重新开始编辑时按新会话初始化。
2. 图片插入成功时从同一份不可变富文本快照获得 HTML 和附件次序。把 SwiftUI 草稿发布安排到本次 `updateUIView` 返回后，按题 ID、会话 ID 和修订号接受发布。当前媒体请求收到完整快照回执才标为插入成功，失败或取消也须解除请求状态并保留原内容。统一使用 `NativeImageAttachment.marker` 和已有的 `NATIVE_IMAGE` 读回规则。图片是有效内容，只有图片的笔记也要保存。对比插入完成、结束输入前后和最终 HTML 中的图片身份及顺序，不能仅比文本长度或张数。该比对在插入及提交边界执行，普通输入继续沿用快照缓存和合并保存。
3. 「完成」先提交输入法，再锁定当前题及会话，选取同源的最新编辑快照。将结束输入时合法的文字变动纳入同一快照。结束过程中若出现附件缺失、回退快照或版本不一致，阻止本次写入，恢复最近的有效草稿并保留编辑界面。用户在点「完成」前主动删除图片或清空正文时，以该次真实编辑状态为准。写入继续通过 `LibraryInlineNoteSaveService` 的串行队列。`onAppear` 调用 `markExistingContentConfirmed` 时只用轻量键标记已读版本，写入状态的 `latestBaseVersion` 仅存 `versionKey(updatedAt:payload:)` 生成的哈希基线。`commitFinishRevision`、自动保存、后台保存及草稿重试共用已注册的写入基线，初次登记从当前编辑捕获的哈希基线取得。保留真正的并发冲突校验，无法验证基线的旧草稿保留供恢复。
4. 写入回执确认当前题的实际 `note` 与该次快照一致后，用同一保存结果更新 `LibraryInlineNoteView.installConfirmedPreview`、`LibraryRecordDetailView.noteBlock` 及详情翻页版本。只读视图与渲染键读取同一个已确认值，详情缓存完成同步后继续使用现有读取路径。冷启动重新读取保存字段时须恢复相同位置和顺序的图片。继续兼容旧内嵌图片标记、HTML 内嵌图片和既有大文档安全渲染，读取错误时保留原内容。预览复用已确认快照及现有缩略图机制。
5. 保留标题行右侧现有状态区和「完成」位置。图片处理时用「正在插入图片…」，已经插入待入队用「等待保存…」，写入时用「保存中…」，本次修订实际确认后才显示「已保存」。纯空白、无任务时状态可省略。附件处理中和重复提交期间停用「完成」，失败沿用状态区和错误反馈「保存失败」，保留图片和重试能力。

## NOTE-02 · 错题笔记与词语库粘贴、保存和打开的格式一致

两条入口分别为错题详情 → 错题笔记，以及学习库／错题详情关联词语 → 新增或编辑词语 →「内容」。以普通段落、标题、句内粗体、缩进、列表和空段作为测试对象。词语库成语及辨析的正文分别继续写入现有 `content`、`comparisonDocument`，错题笔记继续写 `note`。

**源码确认的格式丢失**

1. `RichTextTextView.Coordinator.preparedClipboardText` 会按 Flat RTFD、RTFD、RTF、HTML 的顺序返回第一份可解码的富文本。Markdown 转换在这条返回分支之后。用「`**引申义：**比喻能够赶得上。`」代入现有 `NativeRichTextMarkdown.inline` 规则会得到句内粗体。相同字样若已混进可读的富文本，当前导入会直接保留星号。词语库的 `wordFields` 也走这个分支，现有 HTML 同源段落补全仅在 `noteFormatting` 开启时启用。
2. 词语库的非笔记分支继续跑 `NativeRichTextPastePolicy.compactParagraphSpacing`。段前、段后值超过 4 pt 时被裁剪，缺失或零值不会为独立段落补距。若先选的 RTF 欠缺 HTML 里的结构，选中的几段即使有换行，也可能在视觉上紧挨。保存回读还有一条可构造的差异。`RichTextTextView.normalizeFonts` 从 HTML 标题标签解析字号，`normalizePastedFonts` 会把没有语义标题映射的段落归为 16 pt。用只有 `<p><span style="font-size:21pt">` 的标题送入回读就会降为正文。词语库当前通用 HTML 导出没有对标题角色作往返校验。这些是独立的代码路径。具体剪贴板表示及当次回读的 HTML 由验收记录。

**执行指令**

1. 在 `preparedClipboardText`／`finalizedRichPaste` 按剪贴板项目对比富文本表示。用整段正文、段落顺序和附件证明是同一选区。仅归一行尾，或移除与完整参照比对后可证明为导入器加上的首尾换行。确认 HTML 含有同一完整选区并能保留附件时，使用它的段落、标题、列表、引用和缩进。需要以 RTFD／RTF 保留附件或连续富文本时，复用段落匹配代码从同项 HTML 补足能可靠对齐的结构。正文或段落对不上时保留完整的表示，避免拿没有对齐的 HTML 重排文字、把不同段的标题／格式移过去，或者用无附件的表示覆盖带附件的版本。继续使用现有表格解析和安全降级规则。共享这两处入口需要的导入逻辑，词语库编辑和阅读调用与其序列化配置配对。
2. 独立处理富文本中残留的明确行内 `**粗体**`。只匹配同一段落内、未转义、首尾确实成对的标记，在原富文本范围内去掉标记并合并粗体属性。保留句内位置、已有颜色、斜体、下划线、链接和图片。保护代码、链接目标、转义及单边星号等字面符号。优先保留 HTML 已解析的真实粗体；纯文本 Markdown 复用现有转换。按原选区一次插入并支持一次撤销。格式整理在写入 `textStorage` 前完成，确认后的渲染不补做第二遍。
3. 保留 16 pt 正文和已有标题字号 21／18 pt。错题笔记使用 `NativeRichTextNoteParagraphHTMLPolicy` 的现行笔记规则，识别独立自然段、段内软换行、自动折行和有意空段。词语库中，来源可确认属于不同自然段且缺少有效段距时，取现有 4 pt 段距上限作为相邻正文的段间距，按上一段段后 4 pt、下一段段前 0 pt 实现。来源明确指定的零段距保留，正段距合并按现有上限取一次。普通段内用字号的自然行高，续行及软换行不额外加段距；保留有意空段、列表续行对齐及来源中可确认的缩进。列表、引用、表格和带附件段落延用相应组件的专用排版。窄分屏只改变自动折行，正文尾段在粘贴后即可正常滚动到。
4. 导出时编码已确认的语义标题、段距、软换行及缩进。笔记使用现有带版本的段落属性，词语库可沿用保存 HTML 的方式显式保留标题角色和相应段落属性，并由 `WordLibraryRecordDetailView`／`NativeRichTextDisplay` 及重新编辑共享解码口径。冷读已保存格式只恢复这些属性，避免再次当作外来剪贴板压缩。沿用旧记录兼容与长文安全回读，不对历史资料批量重写。大段剪贴板导入一次，留用现有粘贴后测高和文本输入合并机制。
