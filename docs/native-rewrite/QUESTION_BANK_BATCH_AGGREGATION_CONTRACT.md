# 真题跨卷批次聚合合同 v1

本合同定义多个独立真题包如何进入同一批次索引。它不改变原始试卷、模块、材料、题目、图片、批注及其 ID；不复制题目正文或图片字节；不提供同一试卷的增量合并。已有同卷仍由原导入流程明确选择整卷替换或取消。

## 与单卷导入的关系

- 单文件 JSON 继续使用 `kaogong-question-bank`、`schemaVersion: 1`。根对象可选增加 `batch`；省略它的旧 v1 文件仍按原路径作为单卷导入。
- ZIP 工作簿保持现有合同。没有显式批次元数据的 ZIP 不得从文件名、试卷标题、目录名或工作表文字推断批次。
- 带 `batch` 的文件可以在同一次预览/提交中进入跨卷批次。批次写入与该来源试卷写入必须属于同一 SwiftData 事务；任一步失败，批次、来源台账和映射均不得留下部分状态。
- 若只导入单卷，批次索引不得自动创建。若用户选择把无元数据的旧文件加入批次，界面只询问缺失的必填元数据，并保留现有单卷新增/整卷替换决策。

## JSON `batch` 对象

下面各类共同字段均为必需值：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `family` | string | `national`、`joint` 或 `provincial` |
| `sourceID` | string | 来源文件/抽取来源的稳定标识；同来源修订必须复用 |
| `revision` | string | 来源修订标识；同一来源内容更新时显式改变 |
| `year` | integer | 批次年份，不从 `paper.year`、标题或文件名补齐 |

批次类别的附加字段：

| `family` | 必填字段 | 批次身份键 |
| --- | --- | --- |
| `national` | `volumeID: string`、`volumeName: string` | `national|year|volumeID`；卷别必须由来源明确给出 |
| `joint` | `sessionID: string`、`sessionName: string`、`sourceProvinces: [{code: string, name: string}]` | `joint|year|sessionID`；省份作为来源台账信息，不参与批次键 |
| `provincial` | `provinceCode: string`、`provinceName: string`、`batchID: string`、`batchName: string` | `provincial|year|provinceCode|batchID` |

非该类别字段可省略；若提供则保留来源数据，但不得改变该类别批次键。必填字符串去除首尾空白后不得为空。省份数组必须非空、代码不重复。不能从 `paper.title`、`paper.volume`、`paper.source`、路径、卷内内容或其他来源猜测上述任何值。JSON 解码与校验遇到不完整类别元数据时拒绝预览，不得悄悄降级为另一批次或单卷导入。

`sourceID` 是来源逻辑身份，`revision` 是来源版本。应用另对用户选入的原始 JSON/ZIP 字节计算 SHA-256；该文件摘要不能替代 `sourceID`。同一 `sourceID` 的新修订更新该来源台账和映射，不增加第二条来源。来源摘要相同的再次导入是幂等操作。导入日期由应用记录。

## 批次索引、来源台账及关联

持久化数据仅包含轻量索引：

- 批次索引：批次身份键、类别、年份、明确的展示元数据和派生计数。
- 来源台账：批次 ID、`sourceID`、修订、原文件 SHA-256、来源纸卷 ID、导入时间、来源题目/材料数、新增唯一题目/材料数、已映射重复数、待人工处理数。
- 材料映射：批次与来源纸卷/材料 ID，以及原始规范化指纹；精确相同的材料映射到一个规范来源记录。
- 题目映射：批次与来源纸卷/题目 ID、匹配状态、精确规范化指纹、可选规范来源纸卷/题目 ID及待处理原因。

映射的两端都是已有 `QuestionBankRecord` 中的原始记录。唯一项目自映射为规范项目；精确重复项指向首个已接受的规范来源；疑似项/冲突项保留在来源试卷中并标为待处理，不指向一个未经确认的规范答案。索引不缓存题目 JSON、材料正文、资产字节或整卷副本。批次列表计数可由索引维护，但详情必须沿映射读取原始来源记录。

一个来源包可作为一个来源台账记录。修订替换同一来源之前的映射后再写入新映射，并在一个数据库事务中更新计数；原始已导入试卷仍保留其原始记录。若同纸卷进入既有整卷替换确认，旧来源映射随替换在同一事务中重建/更新，任何已有图片代次只在事务成功后清理。绝不能将不同原卷的图片目录互相删除。

## 精确规范化与判定

仅允许确定性的精确或规范化相等，不使用语义/向量相似度自动去重。文本先做 Unicode NFKC 兼容规范化、换行统一、首尾去空白、连续空白折叠及大小写折叠；不删标点、不改写数字、不调用 AI。

- 材料独立比较：规范化材料正文相等，并且挂接图片的原始字节 SHA-256 集合相等。无正文/无图的空材料不作为跨来源重复合并。
- 题目比较：规范化题干相等、题干图片的原始字节摘要相等、四个选项内容/选项图片摘要形成相同的无序集合、正确选项所指向的选项内容相等，且依赖的材料映射相同。
- A/B/C/D 顺序调整不影响选项集合；保存的原始选项顺序和 ID 不改写。如果选项内容重复导致正确项无法唯一对应，归为冲突待处理。
- 同题干但正确答案不同、选项/图像不同、材料依赖不同、图片裁剪或字节不同、或仅“看起来相似”的内容，不可自动合并。精确相同候选才标记为重复；无法证明相等的条目保留唯一来源并可标记疑似/冲突待处理。

“新唯一”与“重复跳过”仅指批次规范列表如何呈现，不删除来源纸卷中的数据。计数按不同来源修订保持幂等：修订替换后重新计算，不累计旧修订计数。

## 预览、提交和回滚

导入预览须区分新唯一、精确重复、疑似和冲突/待处理数量，并提供来源与批次元数据；只有用户执行一次显式导入/替换操作才写入。解析不完整、图片校验失败、批次元数据冲突或存储失败时，不写入批次台账或映射。原始图片先复制到尚未引用的代次目录，之后才执行包含原纸卷记录、批次、来源台账及全部映射的单一 `ModelContext.transaction`；失败时回滚数据库并删除新代次，成功后仅清理本次被整卷替换的旧代次。

不得静默丢弃疑似重复或冲突问题，不允许 AI 决定删除。任何图片字节差异均可留存并待处理。

## 向后兼容与迁移

- 旧 v1 JSON 没有 `batch` 时仍可导入为单卷；不要求重导入。
- 已存在的原始纸卷、`StoredRecord`、真题批注和资源路径全部保留。批次索引实体以增量模型加入持久化容器；必须用旧模型集合创建的磁盘存储做迁移测试，验证原始记录、批注 payload、资源文件仍可读取。
- 同卷 ID/重复键仍执行显式整卷替换确认。跨卷的批次归组不会改变重复试卷识别逻辑。

## 最小验收覆盖

至少验证：全国同年不同明确卷别分组独立；联考同场次可关联多个省份来源且同材料/异题正确映射；省考按省份+年份+批次隔离；同来源修订幂等；选项重排精确匹配；答案/材料/图像冲突待处理且来源不丢失；失败事务无半提交并保留旧图片/批注；旧数据库新增索引模型迁移保留原记录；旧版同卷重复仍提示整卷替换。
