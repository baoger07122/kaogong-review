# 真题拆解规则主文档

- 规则版本：1.5
- 更新日期：2026-10-11
- 适用范围：公务员考试真题 PDF 拆解、人工核对、标准导入包生成
- 规则维护：主分析对话负责确认规则；真题拆解任务负责执行

## 1. 文档地位

本文档是项目中真题 PDF 拆解与标准导入包制作的唯一规则来源。

- 新规则必须先在主分析对话中讨论、确认，再写入本文档。
- 用户在具体任务中明确提出新的默认交付流程时，按其最新明确要求执行；涉及后续任务默认行为的，只对本规则作必要的最小增补。
- 真题拆解任务不得自行改变全局规则；遇到无法判断的内容必须列入异常清单。
- 单套试卷的临时修正不得直接升级为全局规则，除非主分析对话明确确认。
- 本文档与某次聊天描述冲突时，以用户最新确认并写入本文档的规则为准。

## 2. 职责分工

### 主分析对话

- 分析拆解错误及产生原因。
- 区分单卷特殊情况和可复用的全局规则。
- 与用户确认最终规则。
- 更新本文档，并将变更同步给真题拆解任务。

### 真题拆解任务

- 接收带答案的试卷 PDF。
- 按本文档提取试卷、模块、材料、题目、选项、答案和图片。
- 生成核对样稿与异常清单作为内部核对材料；继续完成可通过系统检查解决的视觉复核、异常修正、结构校验和最终导入包，不以样稿替代最终 JSON，也不常规要求用户逐题审核或确认去重口径。
- 只有原件缺失、关键内容无法可靠判定或确实阻断导入时，才暂停并集中列明受影响题号、缺少的证据及用户需要提供的最小材料；不得猜测补全。
- 不修改 iOS App 代码，不发布 IPA，除非用户在该任务中另有明确要求。

### iOS App

- 默认校验并导入已经确认的 JSON v1；旧版单卷 ZIP 仅保留兼容导入。另有 App 专用的多卷批量更新 ZIP，规则见 `QUESTION_BANK_BATCH_PACKAGE_V1.md`。
- 浏览试卷、模块、材料、题目和图片。
- 不在当前阶段承担 PDF OCR、自动裁图和结构推断。

## 3. 标准工作流程

1. 用户提供带题干和答案的权威 PDF。
2. 为该试卷创建独立输出目录，不与其他试卷混用文件。
3. 提取试卷结构和题目草稿。
4. 渲染并裁取所需图片资源。
5. 生成核对样稿和异常清单，作为内部核对材料；对文字层缺项、图形/材料图片、跨页题及匹配候选，以原页视觉和已有来源记录进行系统侧复核。
6. 修正可由原件可靠确定的内容；未解决项仅在缺少关键证据或确实阻断导入时列为待处理，不得靠猜测补齐。
7. 可继续用标准 Excel 与 `assets/` 作内部校对底稿；样稿和异常清单不得替代最终 JSON。
8. 按 JSON v1 生成单文件 App 交付包，并通过结构、引用、图片字节与哈希校验。旧 ZIP 可保留作兼容验证，不再作为默认交付格式。
9. 将通过校验的单 JSON 文件交付给 App 导入；只有在兼容性验证或用户明确要求时才使用旧 ZIP。

交付位置：最终 JSON 保留在该试卷的独立输出目录，并复制一份到本机
`C:\Users\bao\iCloudDrive\真题拆解\`。文件名必须标明实际覆盖题数；
只包含首批样题时不得命名为“完整版”。复制后核对文件哈希。写入本机 iCloud Drive
目录不等于已确认云端同步；没有同步状态证据时只报告本地文件已写入。

不允许跳过核对阶段直接把不确定内容作为最终包交付；系统能从原件解决的核对项须在任务内完成，不能仅因等待用户逐题确认而停留在样稿阶段。

## 4. 默认 JSON 交付与 ZIP 兼容结构

### App 默认交付：单 JSON 文件

App 默认导入格式为 JSON v1，具体必填字段、类型、校验及大小限制以
`docs/native-rewrite/QUESTION_BANK_IMPORT_JSON_V1.md` 为准。顶层包含
`format="kaogong-question-bank"`、`schemaVersion=1`、`paper`、`modules`、
`materials`、`questions` 和 `assets`。实体字段与原生 `QuestionBankPaper`、
`QuestionBankModule`、`QuestionBankMaterial`、`QuestionBankQuestion` 模型对齐；
选项使用 `id`、`text`、`imageAssetID`。

- 每张图片资源保留稳定元数据，并在同一 JSON 资源记录中附带原始图片字节的纯
  Base64 `dataBase64` 和小写十六进制 SHA-256 `sha256`；`path` 使用
  `assets/<fileName>`。
- 共用材料只保存一次，由适用题目引用；不得将模块标题或说明并入材料或题干。
- Excel 与独立 `assets/` 图片可以继续用于内部整理、人工校对和追溯，但不是 App 的默认交付物。
- 旧 ZIP 结构仅用于兼容；不得因保留 ZIP 兼容而改变稳定 ID、材料引用或图片关联。

批量题库更新包是 App 的多卷更新格式，不是 PDF 拆解任务的默认交付物。它只按精确 `paperID` 和 `questionID` 更新；新题需在预览中逐题明确勾选，且更新前会备份将覆盖的原始 payload。具体 ZIP 清单、图片和保留策略见 `QUESTION_BANK_BATCH_PACKAGE_V1.md`。

### ZIP 兼容结构（非默认交付）

一个 ZIP 只能包含一套试卷，根目录结构为：

```text
试卷名称.zip
├── 真题导入.xlsx
└── assets/
    ├── image-001.png
    └── image-002.png
```

规则：

- ZIP 根目录只能有一个标准 `.xlsx` 工作簿。
- 图片必须作为独立文件放在 `assets/`，不得写成 Base64 或嵌入列表记录。
- 工作簿至少包含：`导入说明`、`试卷`、`模块`、`材料`、`题目`、`图片资源`。
- 试卷、模块、材料、题目和图片都必须具有稳定且不重复的 ID。
- 表内所有关联必须能解析到现有记录。

现有验证结构参考：

- `outputs/question-bank-validation/核对样稿/拆分核对样稿.md`
- `outputs/question-bank-validation/2019国考地市级真题验证包/`

## 5. 试卷与模块规则

### 试卷

保存以下信息：

- 稳定试卷 ID
- 试卷名称
- 年份
- 考试类型
- 卷别
- 来源
- 导入版本

带答案 PDF 由用户确认可直接作为权威来源时，以该版本的题干、选项和答案为准，不再擅自与其他网络版本拼接。

### 模块

- 模块标题、模块序号和模块作答说明必须独立保存在模块表。
- 行测的一至五模块标题应作为试卷结构保存。
- `五、资料分析`、`四、判断推理`等模块标题不得写入材料或题干。
- 模块开头的通用作答说明不得写入第一道题的题干。

## 6. 材料与题目规则

### 普通文字题

- 每道题分别保存题号、题干、A-D 选项和正确答案。
- 不把页眉、页脚、页码、模块标题或作答说明混入题干。
- 保留题干中的必要换行、空格、公式和标点，不进行改变含义的润色。
- 选项文字不得包含多余的 `A.`、`B.` 等前缀；选项字母由结构字段保存。
- 逻辑填空包含两个或更多空位时，A-D 每个选项里的词语组合必须逐项核对原卷，按空位顺序用 `；` 分隔，例如 `第一空词语；第二空词语`，不得把词组粘成一整句。仅凭连续中文文本无法可靠推断词语边界；原卷看不清时保留原文并列入人工核对，不自动猜分隔点。

### 共用材料题

- 共用材料只保存一次，使用稳定材料 ID。
- 每道题通过材料 ID 引用同一材料。
- 每道题仍须分别保存自己的题干、选项和答案。
- 资料分析通常五道题共用一份材料，但必须以原卷实际分组为准，不机械地每五题强制分组。
- 跨页材料必须合并完整，不能因分页重复或遗漏段落。

### 题目答案

- 正确答案必须来自用户确认的带答案版本。
- 答案只允许使用当前题目真实存在的选项字母。
- 无法确认答案时进入异常清单，不得猜测。
- 当前阶段不自动生成答案解析；原文件有明确解析时可以原文保存，没有时留空。

## 7. 图片拆解规则

### 通用规则

- 图片裁剪必须清晰，优先使用高分辨率页面渲染。
- 图片仅保留题目需要的内容，去除页眉、页脚、页码及相邻题目。
- 不改变图表比例，不拉伸，不重新绘制造成数值或视觉关系变化。
- 裁剪不确定时必须提供预览供用户核对。
- 图片文件名、资源 ID、所属记录和用途必须一一对应。

### 图形推理

- 一道图推题只保存一张完整题图。
- 完整题图同时包含题干图形、问号位置和 A-D 四个图形选项。
- 不拆成“题干图＋四张选项图”。
- 选项字段仍保存纯文字 `A`、`B`、`C`、`D`。
- 四个选项不再分别关联图片资源。

### 资料分析材料图片

- 共用图表作为材料图片保存，并由同组题目共同引用。
- `五、资料分析`及模块作答说明不能进入材料图片。
- 材料图片必须完整包含作答所需的表格、图例、单位、标题和注释。

### 资料分析图片选项

- 图片型选项分别裁剪为 A、B、C、D 四张独立图片。
- 每张图片只保留该选项的图形内容。
- 裁剪不得夹带题干、其他选项、选项字母或无关文字。
- 选项字母仍由题目结构字段保存，不烧录进选项图片。

## 8. 文字清理规则

- 清除 PDF 提取产生的无意义断行，但保留真实段落边界。
- 题干正文与独立提问句在原卷中另起一行或语义上构成独立句时，应在 JSON `stem` 中用 `\n` 保留边界；PDF 栏宽导致的自然折行应合并。不得把所有物理换行一律压成空格，也不得不加判断地保留每个折行。
- 修复明显由跨行造成的拆字，不擅自改写原文。
- 连续下划线、横线空位、公式、百分号、单位和引号必须保留。逻辑填空里的空位不得因空白清理而消失；若文字层只留下短空格，先对照原页，确认后才用一致的空位占位符补回，不推测答案字数。
- 言语理解等段落型题目须抽样回看原页，至少检查正文/独立提问句的换行和填空横线；跨页或多段结构不清时逐题核实，不批量插入未经来源支持的换行。
- OCR 无法确定的字词不得凭语感替换，应标记原页位置进入异常清单。
- 题干和选项之间必须通过字段分离，不依赖字符串中的编号判断。

## 9. 稳定 ID 与命名

建议格式：

```text
试卷：gk-2019-city
模块：gk-2019-city-module-4
材料：gk-2019-city-material-111-115
题目：gk-2019-city-q071
图片：gk-2019-city-q071-full-figure
```

要求：

- 同一试卷重新生成时继续使用原稳定 ID。
- 不以随机 UUID 替代已确定的稳定 ID。
- 题号在同一试卷内不得冲突。
- 图片 ID、文件名和表格关联保持稳定。

## 10. 核对样稿

正式打包前必须生成核对样稿，至少包含下列内容，作为系统内部核对记录；可随最终成果附带，但不得单独作为完成交付：

- 试卷基本信息。
- 模块标题、顺序和说明。
- 每道抽检题的题号、题干、选项和答案。
- 共用材料与适用题号。
- 图推完整题图。
- 资料分析材料图。
- 图片型选项的四张独立裁图。
- 无法确定、可能缺失或跨页异常的项目。

核对结果分为：

- 已确认：可以进入最终包。
- 待确认：不得进入最终包。
- 单卷特殊处理：只影响当前试卷。
- 建议全局规则：返回主分析对话讨论，确认后更新本文档。

## 11. 最终校验

默认交付的 JSON 必须检查：

- 试卷 ID 和题号无重复。
- 模块、材料、题目、图片关联完整。
- 答案有效。
- 每张图片的 Base64 可解码；解码后的原始字节与声明的 SHA-256 一致，格式与 MIME 类型一致。
- 没有未被引用的图片。
- 没有材料或题目引用缺失图片。
- 模块标题未混入材料或题干。
- 图推为一张完整题图。
- 资料分析共用材料只保存一次。
- 图片型选项裁剪不含题干和选项字母。
- 运行通用预检 `python tools/question-bank/preflight_question_bank_json.py <JSON路径>`；项目内 JSON 导出脚本必须在写出最终文件前调用同一预检。任何预检错误均阻断最终交付，并报告题号/材料、期望映射和实际映射。
- 图片用途按导入器的引用关系精确匹配：题干图片 `ownerType=question`、`ownerID=题目ID`、`role=题干整图`；选项图片 `ownerType=option`、`ownerID=题目ID`、`role=选项A/B/C/D`；材料图片 `ownerType=material`、`ownerID=材料ID`、`role=共用材料`。不以“图表”“插图”“完整题图”等描述性变体替代固定用途值。

若生成旧 ZIP 兼容包，还需检查工作簿、`assets/` 路径和 ZIP 根目录结构符合本节之前的 ZIP 规则。

App 导入测试另需确认：

- 导入失败不会留下半套试卷。
- 重复导入能被识别，不静默创建重复试卷。

## 12. 当前边界

当前真题拆解流程负责生成可导入、可浏览的数据，不包含：

- 自动作答流程
- 计时与交卷
- 成绩统计
- 自动生成答案解析
- 在 iPad App 内直接解析 PDF

这些能力后续开发时不得反向破坏本文档确定的导入结构和稳定 ID。

## 13. 既有题库补答案与渐进合卷

### 唯一底稿与任务边界

- 每次增补都以用户明确指定的最新 canonical JSON 为唯一底稿；记录其路径和修改前 SHA-256。不得按文件名、修改时间或“看起来最新”自行挑选另一个 JSON。
- 先在工作副本中修改并校验；通过后才交付。除用户明确要求替换外，不覆盖用户指定的底稿。
- 没有新答案 PDF 或新试卷时，只做规则、脚本准备或核验说明；不得重跑旧卷 OCR、重建题库或改写已完成交付物。

### 仅补充或核对答案

- 先按规范化题干和 A-D 选项的原顺序匹配；题号只用于定位来源页，不能单独作为匹配依据。
- 图形题、图片选项、OCR 漏字或多个候选题干相同时，必须核对 PDF 页面图像与现有题图/选项资源，并把人工核对依据写入对应 provenance.evidence。无法唯一匹配时不写答案，列为待确认。
- 补答案任务只允许修改 `answer`，以及记录答案来源所需的 `sourcePapers` 和题目 `provenance`。已有题目的 ID、paperID、显示题号、题干、选项、材料关系、图片资源及其 ID、字节和 SHA-256 必须保持不变；不重抽或重裁已有图片。
- 新答案 PDF 的文件名及 SHA-256 作为来源记录写入同一 JSON 的 `sourcePapers`；每道被核对题在 `provenance` 中记录源卷 ID、原题号、原页码和答案依据。PDF 标注来源不是官方发布时，应明确写明其非官方性质，不得升级表述为官方标准答案。
- 若新答案与已有答案冲突，不静默覆盖。保留原值并记录新旧答案、来源及不确定性；只有用户明确裁定后才更新答案，同时在 provenance.evidence 中记录裁定依据。

### 新卷逐批合并

- 每批新卷都以用户指定的 canonical JSON 为底稿。先依据规范化题干、A-D 有序选项、材料关系及必要的图片内容找同题候选；仅凭原题号、题目位置或答案字母不得去重。
- 题干、选项顺序/内容、必要图像和答案一致且匹配唯一时，保留一条题目记录，将新来源追加到该题的 provenance，不重复新增题目。
- 出现选项顺序、题意或答案冲突时，不自动合并或覆盖；保留证据并进入异常项，待明确裁定后处理。对无法判断是否同题的情况也不得猜测。
- 仅把确认属于本次 canonical 试卷、且底稿中不存在的独有题目追加到 `questions`。所有既有题目、材料、模块和图片 ID 必须原样保留；新实体只分配一次稳定 ID，之后的修订沿用，不得批量重生成 ID。
- 复用已确认相同的材料和图片资源。只有确属新题且底稿无对应资源时才新增图片；不为“统一格式”重抽旧图。新增资源必须具有稳定 ID、SHA-256 和有效的题目/选项/材料引用。
- 可按省份或卷别分批追加，不要求等到全部联考来源齐全。每个新来源均写入同一 JSON 的 `sourcePapers`，对应题目和材料追加 provenance；Excel、聊天记录或独立台账仅可作临时工作文件，不作为唯一来源凭证。

### 试卷身份、修订与替换

- 同一 canonical 考试集合的答案修正、错字修正或同一卷的更正版本，保持 `paper.id` 不变；使用 `importVersion` 标记交付修订，并保留完整来源文件名、SHA-256 与 provenance。
- `paper.id` 表示稳定的 canonical 试卷身份，不随新省份来源逐批加入而变化。只有确认属于同一考试批次、科目和卷别/版本时，才继续追加到该 canonical JSON。
- 年份、考试、科目、批次或卷别实质不同的试卷必须使用不同 `paper.id`，不得误当成旧卷修订并替换。身份不明时暂停自动替换，列出差异待确认。
- 本规则约束数据身份，不代表当前 App 已实现安全替换。App 端的同 `paper.id` 替换、版本比较和旧作答/涂鸦数据保留行为需另行验证；本规则准备不授权修改 App 代码或发布 IPA。

### 每次增补的验收与摘要

- 答案增补前后核对题目数量及全部既有题目 ID、paperID、题干、选项、材料/图片关联；确认图片 ID、字节哈希无变化。差异应仅限获准的答案及来源字段。
- 渐进合卷须核对新增题、去重题、未解决候选、答案冲突、材料/图片引用、ID 唯一性，以及 JSON 大小和所有图片字节/哈希限制。
- 每次交付摘要至少列明：新增题数、去重数、补答案数、答案冲突/待确认项、既有 ID 保留检查、图片引用/哈希检查，以及最终 JSON 路径和 SHA-256。
- 复制到本机 iCloud Drive 目录后核对文件 SHA-256；除非另有同步状态证据，只报告本地目录写入，不声称云端同步已完成。
