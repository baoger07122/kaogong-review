# 原生统一交互库与准入规则

> 本文控制原生 App 的跨页面交互。任何页面不得临时创造新的弹窗、选择器、删除方式、反馈样式或手势规则。

## 1. 强制准入流程

1. 先检查统一交互库是否已有满足需求的组件；已有组件必须直接复用。
2. 现有组件确实无法覆盖时，先登记交互编号、使用场景、触发方式、完整状态、动画、触感、键盘、安全区、分屏和无障碍要求。
3. 在 Swift Playgrounds UI 实验室制作可操作预览，不得直接写入正式业务页。
4. 用户明确回复“确定预览”后，才能把规则标记为“已确认”。
5. 已确认组件迁移到 `native-ios/Sources/DesignSystem/` 的统一交互库，业务页只能调用，不得复制后改样式。
6. 后续如需改变已确认规则，按新增规则重新预览和确认，不得静默修改。

状态含义：`候选` = 已登记但未确认；`预览中` = 可在 UI 实验室操作；`已确认` = 可进入正式组件库；`已废止` = 不再允许新页面使用。

## 4. 当前 UI 实验室确认基线

- 2026-08-27 用户已回复当前版本可以确定；以下内容冻结为暂行全局 UI 基线，后续变化仍需重新预览确认。
- 字体采用 iOS 系统中文字体（系统自动使用苹方）；页面标题 22pt/Semibold，分区标题 16pt/Semibold，卡片标题 14pt/Medium，错题题干和正文 13pt/Regular，辅助文字 11pt/Regular；表单和弹窗中的文字输入框内容为 13pt。
- 上述 13pt 题干来自 Web 稳定版错题画廊；Web 全局正文为 14px。原生界面仍需以 iPad 真机视觉密度为最终确认标准，不能把 CSS px 与 iOS pt 当作绝对等价单位。
- 主导航内容高度由 52pt 降为 44pt，图标 18pt、文字 10pt，上下内边距一致；系统底部安全区必须保留。
- 新增弹窗使用居中缩放+淡入动画，不显示底部取消按钮，仅保留一个居中保存按钮；右上角关闭入口保留。
- 删除确认使用自定义居中弹窗，删除在左、取消在右。
- 表单属性和日期改为点击行后弹窗选择，不使用横向分段选择器。
- 成功状态使用低饱和蓝绿色和 `checkmark.seal.fill`。

## 5. 系统窗口控件边界

iPad 的多任务/窗口控件属于系统界面，App 不能把它任意移动到自定义坐标。2026-08-28 已在同一台 iPad 上依次真机验证默认配置、`unified`、`minimal`、纯 UIKit `UIWindowSceneDelegate` 以及 `unified + UINavigationBar`；三点控件均未移动到与系统时间相同的一行。因此不得再通过页面内边距、隐藏安全区或自定义绘制来模拟移动系统控件。

正式页面采用以下规避规则：

- 页面主标题不要求围绕三点控件居中，也不以主标题是否被占位作为验收标准。
- 左上角返回按钮、关闭按钮及其他可点击控件必须位于系统安全区域内，不得被三点控件覆盖。
- 返回按钮优先使用系统导航栏提供的安全布局；确需自定义时，必须读取安全区/窗口控件适配后的布局边界，不允许写死顶部坐标。
- 主要半屏、较窄分屏、全屏和旋转后均需真机检查返回按钮可见、可点击，且最小点击区域完整。
- 本问题记录为 iPadOS 系统窗口行为限制，不再阻塞业务页面重写；若苹果后续提供新的公开接口，再单独立项复验。
