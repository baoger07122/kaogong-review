## 1. 返回/退出按钮 · iPad 分屏右移（规避系统侧边指示条）

### 现象
iPad 分屏（Split View / Slide Over）时，系统在屏幕**左边缘**显示侧边指示条，会遮挡页面左上角的返回/退出按钮。

### 方案（v8.5.3 起，通用 class 机制）
给「左上角有返回/退出按钮的页面」**容器**加一个 class：

```html
<section id="page-xxx" class="page ipad-back-shift" ...></section>
```

CSS 会自动生效（`src/styles.css`）：

```css
/* 分屏时按钮右移 24px（只动按钮，不动标题栏/页面） */
body.ipad-split .ipad-back-shift .page-header__back,
body.ipad-split .ipad-back-shift .sc-back-btn {
  margin-left: 24px;
  transition: margin-left 0.2s ease;
}
/* 窄窗口（<=400px，Slide Over）再让到 32px */
@media screen and (max-width: 400px) {
  body.ipad-split .ipad-back-shift .page-header__back,
  body.ipad-split .ipad-back-shift .sc-back-btn { margin-left: 32px; }
}
```

支持两种退出按钮形态：
- `App.Components.pageHeader(...)` 生成的 `.page-header__back`（绝大多数页面）
- 速算练习自定义的 `.sc-back-btn`（练习中页面）

### 已应用页面
| 页面 | 容器 id | 按钮形态 |
|---|---|---|
| 错题详情 / 错题编辑 | `#page-error-detail` / `#page-error-form` | pageHeader |
| 笔记详情 / 笔记编辑 | `#page-note-detail` / `#page-note-form` | pageHeader |
| 便签管理 | `#page-stickies` | pageHeader |
| 速算练习（全部视图） | `#page-speed-calc` | pageHeader + sc-back-btn |

### 后续新增页面的延续操作（重要）
1. 新页面左上角有返回/退出按钮 → 容器 class 加上 `ipad-back-shift`，**无需改 CSS**。
2. 若新按钮不是 `.page-header__back` / `.sc-back-btn` 形态 → 把按钮类名追加到上述 CSS 选择器（并更新本表）。

## 2. 版本号规则（用户约定）

- 格式 `X.Y.Z`：`X.Y` = **月.日**（如 8.5 = 8 月 5 日），`Z` = 当天迭代号从 1 起。
- 改版本号前**先查线上当前版本**（`curl -s https://kaogong-review.onrender.com | grep -o "App.VERSION = '[0-9.]*'"`）：
  - 日期未变 → 末尾数字 +1
  - 跨天 → 改日期部分，末尾从 1 重新计（勿把末尾数字当主版本号 +1）

## 3. 构建 / 部署流程

```bash

for f in test_*.js; do NODE_PATH="C:/Users/bao/.workbuddy/binaries/node/workspace/node_modules" node "$f" | tail -3; done
git add -A && git commit -m "vX.Y.Z 描述..."
git -c http.proxy= -c http.connectTimeout=25 push origin main   # 直连；失败则 node 轮询重推（网络抖动常见）
# Render 自动部署，线上地址不变：https://kaogong-review.onrender.com
```

前端源码按依赖层次拆分在 src/core/、src/components/、src/pages/、src/bootstrap/、src/styles/ 和 src/modules/，
src/app.js 是入口说明文件，
顺序由 build.js 中的 JS_MODULES 显式维护。01-sketch-preserved.js 中的涂鸦实现、
150-speed-preserved.js 中的速算实现只参与拼接，修改其他模块时不得改写这两块。

设置、考点/错因管理和词语库页面分别位于 src/pages/60-settings.js、
src/pages/61-kp-manage.js 和 src/pages/62-worddb.js；笔记类型数据服务位于
src/core/60-note-types.js，全局编辑器与 Service Worker 启动入口位于
src/bootstrap/00-editor-entry.js。

CSS 按原有级联顺序拆分在 src/styles/，src/styles.css 只作为说明清单；
其中 71-sketch-preserved.css、90-speed-preserved.css 和 92-speed-preserved.css
是涂鸦、速算的受保护样式片段。

build.js 中显式列出的文件拼接生成。

云端后端入口仍是 server/server.js，配置、数据库、认证、静态资源保护和 API 路由

## 4. 测试约定

- 测试文件 `test_*.js` 用 jsdom 跑（`NODE_PATH` 指到 managed workspace 的 node_modules）。
- 版本断言在部分测试里存在（`App.VERSION === 'X.Y.Z'`），升版本时同步 sed 更新。
- jsdom 不支持 CSS 变量 `var()` 计算值（圆角/字号用变量时不要断言 computed value）；CSS 类、字面量属性（如 `width:150px`）可正常断言。
- 结构重构验收重点为构建、整包语法、核心页面/编辑器/备份/便签测试；`test_speedcalc.js` 仍包含旧版自定义练习双配置和评级位置断言，速算实现按约定不在重构中修改，需作为独立功能专项处理。

## 5. 笔记数据架构（v8.5.5 起：彻底去块）

### 存储
- 笔记 `content` 统一为**完整 HTML 字符串**（所见即所得直存，格式 100% 保真，不再 JSON 块/Markdown）
- 历史数据（JSON 块数组 / 旧 MD）在**打开笔记时**由 `App.Utils.toNoteHtml()` 自动迁移写回（用户无感）
- `toNoteHtml` 幂等：已是 HTML 原样返回，绝不二次转换（编辑产物永不变形）

### 编辑器
- 笔记编辑用 `App.Components.htmlEditor(initialHtml, opts)`：**单个 contenteditable 连续富文本区**
- 保存：`getHtml()` = 编辑区 innerHTML 直存；`setHtml(h)` / `focusAtEnd()` / `.area`（编辑区 DOM）
- 格式：B/I/U/S/行内代码/颜色/高亮（行内，选区保持机制沿用 v8.4.17）；H1-3/正文/引用（段落级，**手动 DOM 包裹**，不依赖 execCommand formatBlock，移动端可靠）；无序/有序（execCommand）；公式（mformula 节点，`data-latex` 保源码）
- 桌面工具栏 `.html-editor__toolbar`（复用 notion-tool-btn 样式，移动端隐藏）；移动端走底部格式面板（注册到移动工具栏单例）

### 查看
- 详情页查看直接渲染 `note.content`（HTML 直通），容器 `.note-html-body`（原生标签样式与编辑区对齐 → 编辑查看所见即所得）
- 迁移产物（toNoteHtml 输出）仍带 md-preview-* class，样式兼容

### 去块后的注意
- notionEditor / renderBlocks / mdToBlocks 代码保留（toNoteHtml 内部 + 错题等场景依赖），**不要再对笔记 content 按 JSON 数组处理**
- 列表搜索：笔记搜索对 content 直接字符串匹配（标签会干扰关键词，后续可优化去标签）
